# Audit — Fabric VR v1 (2026-09-19)

Subject: branch `feat/v1-notes-core` @ `7c0b438` (the build installed on the operator's Quest 3).
Plan and method: [`2026-09-19-v1-audit-plan.md`](2026-09-19-v1-audit-plan.md). Raw inputs from the three
independent reviewers: [`inputs/`](inputs/). This document holds the **merged, de-duplicated and
verified** findings — every row below was checked against the code or a build artefact by the author
after the reviewers reported it; where a claim can only be settled on the headset it says
**(device-verify)** and names the observation.

## Verdict in one paragraph

The build is installable and launches, the storage and search core is sound and tested, and the
security posture of the key is basically right. **But the product's premise — hold a button, speak,
get a note — very likely does not work on the device as shipped**, for a reason no unit test could
see: the hold gesture opens a `Dialog`, and the new window cancels the very press that started it.
Three more Blockers sit behind it: the same sheet would crash the immersive Space (no
`ActivityResultRegistryOwner` under a plain `android.app.Activity`), a LAN whisper-server over
`http://` is silently refused by Android's cleartext policy, and deleting a note removes its vault
file from the wrong month's folder, leaving the file forever. None of these was caught by the 60
green tests, because each lives at a seam the tests do not cross: window ↔ gesture, panel ↔ owner,
OS policy ↔ URL, mirror ↔ timestamp. That is the lesson of this audit, and the hardening plan
adds a device suite and seam tests before it adds features.

Counts after merging 75 raw rows: **5 Blocker · 15 High · 26 Medium · 12 Low** = 58 distinct
findings, plus 4 documentation divergences.

## 7. What holds (verified by at least two readers)

Manifest = spec §3.1 line for line; panel geometry 1843 × 1152 px inside the ceiling; the Home
`PendingIntent` return path exact; passthrough on; `language="auto"` + `detect_language=false` is
exactly right for whisper.cpp v1.9.4 (`detect_language=true` would return **without transcribing**);
`lang` lifetime and `JNI_ABORT` correct; GCM IV fresh per encrypt; the key never reaches a log,
`toString` or a body; `allowBackup=false` applies to debug; the submodule is v1.9.4; FTS↔Room sync in
one transaction; tags re-derived on save; blank-query short-circuit; `TagParser` look-behind; SSE
classification; backpressure fixed and fenced by a 400-token test; no-key makes no request; router
ordering; every DAO call is `suspend`/`Flow`; buffer lock + `cancelAndJoin` closes the recording race;
autosave flushes on Back and dispose; contrast 6.7:1; elapsed seconds correct; `viewModel()` resolves per
back-stack entry and, inside the Spatial panel, against a panel-local `PanelViewLifecycleOwner` store.

## 8. Why the tests were green

Each Blocker sits at a seam the JVM suite cannot cross: **gesture ↔ window** (AUD-01) needs a real
window manager; **panel ↔ owner** (AUD-02) needs the Spatial runtime; **URL ↔ OS policy** (AUD-04)
needs Android's network stack; **mirror ↔ timestamp** (AUD-05) was testable and simply untested —
the vault test passed `createdAt` directly instead of driving the mirror. The hardening plan
therefore opens with an instrumented device suite and a `VaultMirror` test, and every fix below
names the test that would have caught it.
