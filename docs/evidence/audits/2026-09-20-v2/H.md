## Minimum CI

The failures this project has actually had, and which trigger would have caught each:

| What actually happened | Caught by |
|---|---|
| `check-secrets.sh` greped nothing for an unknown period; ten planted credentials passed (`f7d656d`) | the gate's own canary, run on **every push** — the canary now exists, nothing runs it |
| Two instrumented tests went red and nobody noticed for three commits (F-02/F-03) | **cannot** be caught on a hosted runner — see the device-gate ledger below |
| A handoff claimed "13 tests, 0 failures" while two were red (F-03) | the ledger check: a push touching `androidTest` with no matching ledger row **fails** |
| `assembleRelease` had never been attempted until this audit | `assembleRelease` on **push to the working branch** |
| JVM suite counts quoted as 115 / 96 / "13 green" in three documents | the job's own summary line, which is the only number anyone should quote |

### The workflow

One file, `.github/workflows/ci.yml`. Two jobs.

**Job `checks` — on `push` (any branch) and `pull_request`.** `ubuntu-latest`, `actions/setup-java@v4`
with `temurin` 17 (or 21 — it must match H-37's decision), `gradle/actions/setup-gradle@v4` for the
cache. Checkout **with `submodules: recursive`**.

```
bash scripts/check-secrets.sh          # ~2 s   — canary-guarded, so a green means it ran
bash scripts/check-docs.sh             # ~5 s   — needs its own canary first (H-12)
python3 docs/ux/lint.py                # ~1 s
./gradlew --no-daemon testDebugUnitTest lintDebug   # ~4–6 min cold, ~90 s warm
```

**Job `release` — on `push` to the working branch and to `main`.** Same setup plus the Android SDK
licence acceptance (H-38) and the NDK. `./gradlew --no-daemon :app:assembleRelease -PversionCode=${{ github.run_number }}`.
This is the job that pays for the NDK: the whisper.cpp arm64 build is ~3–4 min cold, near-free with
the `~/.gradle` and `.cxx` caches warm. Upload the APK as an artifact — which makes H-32's delivery
story one `gh release upload` away. Add C-13's signing gate here.

**Cost.** Both jobs, cold, ~12 min of a free-tier runner; warm, ~4. For a repository with two
commits a day that is comfortably inside GitHub's free minutes for a private repo, and it is zero if
`main` is ever made public.

### What it cannot catch, stated plainly

Everything that needs a headset. No hosted runner can run `connectedDebugAndroidTest`: it needs
arm64, Horizon OS, a 190 MB model on the device, and — for `PanelSmokeTest` and
`ImmersiveLaunchTest` — the Spatial SDK runtime. **Do not fake it with an x86 emulator; it would go
green on a platform the app does not ship to, which is worse than no signal.** Nor can CI catch the
things the v2 merge listed as unsettleable: on-head legibility, hit rate at real distance,
transcription quality across voices, whether the IME appears for a Spatial panel at all.

The honest substitute is the ledger in **H-10**: `docs/evidence/device-gate.md`, one row per real
device run, and a CI check that **fails** a push touching `androidTest` sources when the newest row's
commit is not an ancestor of `HEAD`. It does not run the tests. It makes it impossible to ship a
change to them while pretending they ran — which is the exact failure F-03 recorded.

**What not to build.** No matrix across API levels (one target, Horizon OS 69 / Android 14). No
coverage gate (the suite is young; a threshold would be a number nobody chose). No nightly
dependency-update bot until H-13's verification metadata exists, or every bump becomes an unverified
resolution. No self-hosted runner with a headset attached — for two devices the cost of maintaining
it exceeds the cost of a human putting the headset on and pasting a line into the ledger.

## Upgrade path

A person has notes, the 190 MB model, a saved OpenRouter key, a saved whisper-server URL and their
settings. A new APK is installed over it. What survives, in order of how it breaks:

**1. The signer change destroys everything, and it is the next planned upgrade (H-23 — Blocker).**
Both headsets carry a debug-signed APK. The release APK is signed with a different key, so
`install -r` fails and only `adb uninstall` clears the way. `filesDir` goes with it: the Room
database, the entire vault, the model, the Keystore-encrypted keys. `allowBackup="false"` means no
`adb backup`. There is no export in the app. **This is the first upgrade that will lose someone's
data, and it is on the critical path of the work axis C recommends.** What prevents it: a vault
export before the cut-over, and an import to restore afterwards.

**2. Room survives version 2→2 and is a cliff at 3 (H-24 — Blocker).** `install -r` at the same
schema preserves the database intact; `MIGRATION_1_2` runs correctly for a device still on v1 (with
A-12's caveat that it deletes duplicate-`dayKey` rows and their text). At version 3 — which **E-20
already proposes**, for the FTS unicode61 tokenizer — Room needs a route from *every* live version.
A single `MIGRATION_2_3` leaves a v1 device with
`IllegalStateException: A migration from 1 to 3 was required but not found` on **every launch**: the
app never starts again. And the architecture's stated recovery does not exist — `CONTEXT.md` says the
database is "an index over" the vault, but `MarkdownSerializer.parse()` is called only from tests
(H-24). The Markdown files survive on disk and nothing can read them back.

**3. The v1 schema cannot be tested against (H-25 — High).** `core-notes/schemas/` holds `2.json`
only. `MigrationTestHelper` builds old databases from exported JSON, so `MIGRATION_1_2` is
untestable and A-12's proposed test cannot be written.

**4. The Keystore alias survives the install and dies with the uninstall (H-23, H-28).**
`fabricvr_settings_v1` is scoped to the app's uid; `install -r` keeps it and every encrypted value
decrypts. The uninstall in (1) destroys the alias, and `KeystoreSecureSettings.get` then correctly
reports the values as *absent* rather than *unreadable* (the distinction `DEC-0006` was built for) —
because the SharedPreferences went too. Separately, the keys are also sitting in plaintext
saved-instance-state whenever Settings has been visited (H-28).

**5. `KEY_WHISPER_SERVER_URL` now routes nowhere, silently and invisibly (H-26 — Blocker).** The
value survives perfectly and does nothing. `SttProvider.byKey(null)` → `LOCAL`, so
`Graph.sttEngine()` builds `SttRouter(local, remote = null)` and the configured server is never
tried. The Settings field that would reveal the stored URL renders only when the provider is already
`SERVER` (`SettingsScreen.kt:238`), so the person cannot see it either. **`DEC-0014`'s own
Consequences section names this exact outcome; nothing implements the carry-over.** Ten lines in
`Graph.init` fix it.

**6. The model file survives `install -r` and costs 190 MB after any uninstall (H-29).**

**7. The vault survives, with a hole nobody can see (H-27).** `VaultMirror`'s pending-retry queue is
in memory. A note whose vault write failed before a restart is in the database and not on disk, and
the failure state is gone.

**8. `rememberSaveable` state is irrelevant to upgrades** — the process is replaced, the saved-state
Bundle is discarded, and every screen re-reads from `SecureSettings` on entry. Its problem is
confidentiality (H-28), not persistence.

## Fresh-clone reproducibility

The exact walk, on a second macOS machine with Android Studio installed. **Steps that fail are
marked.**

1. **`git clone git@github.com:passioncode-ai/fabric-vr.git` — FAILS (soft).** SSH to a private
   org repo: needs a key with access. HTTPS + a PAT works. `origin` is
   `git@github.com:passioncode-ai/fabric-vr.git`; the README names no clone command at all, so the
   reader has to know. *(One README line. Not filed separately — it belongs with H-36.)*
2. **`cd fabric-vr && ls` — FAILS (hard, H-36).** The default branch is `main` @ `0dcadae`:
   `README.md` and `docs/` and nothing else. No `gradlew`, no `settings.gradle.kts`, no
   `.gitmodules`. The README says "Research complete, no code yet" and never names
   `feat/v1-notes-core`. **A fresh clone stops here**, and nothing on the page tells the reader why.
   → `git checkout feat/v1-notes-core`.
3. `git submodule update --init --recursive` — **works.** Fetches `ggml-org/whisper.cpp` over HTTPS
   (no key needed) at `927cfce3…` = v1.9.4. `--recursive` is a no-op: whisper.cpp v1.9.4 has no
   submodules of its own and ggml is vendored (H-21).
4. `echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties` — **works.** Correctly gitignored
   and enforced by `check-secrets.sh`.
5. **`export JAVA_HOME=…/Android Studio.app/Contents/jbr/Contents/Home` — FAILS if forgotten
   (H-37).** Nothing in the build enforces it. Gradle 8.13 does not run on JDK ≥ 24; a machine whose
   default `java` is newer fails with a class-file-version message that names neither the JDK nor
   `JAVA_HOME`. No toolchain block, no foojay resolver, no `org.gradle.java.home`.
6. **SDK licences — FAILS on a machine that has never accepted them (H-38).** AGP will download
   NDK 27.2.12479018 and CMake 3.22.1 itself, but only after `sdkmanager --licenses`. That command
   appears **nowhere** in the repository. The error arrives at the first `./gradlew` and reads like a
   project defect.
7. `./gradlew :app:assembleDebug` — **works once 5 and 6 are done.** The wrapper downloads Gradle
   8.13 and **verifies it against a checksum that is correct** (H-14, verified against the published
   sum on 2026-09-20). `compileSdk 35` and build-tools are fetched. CMake builds whisper.cpp for
   arm64-v8a with the armv8.2 flags. *Not re-run here — axis C measured `assembleRelease` exit 0 at
   this commit.*
8. **Dependency resolution — succeeds, and is unverified (H-13).** ~120 artifacts from
   `mavenCentral()` and `google()`, no checksums, no lockfile. A different day could resolve
   differently for any unpinned transitive; nothing would say so.
9. **`cp keystore.properties.sample keystore.properties` — INCOMPLETE (H-34).** The sample has five
   keys and no `keytool` command; no document says how to create `release.keystore`, where the real
   one lives, or who holds it. Without it the release build succeeds and produces an **unsigned** APK
   (C-13) that no headset will install.
10. `adb connect <ip>:5555 && bash scripts/install-on-quest.sh` — **works for one headset, is
    arbitrary for two (H-30).** With two devices listed the script silently picks the first, prints
    `connected.`, and never names which one. It also never checks that the installed build is the one
    just compiled (H-11), and the versionCode it installs is `1` regardless (H-31).
11. `./gradlew testDebugUnitTest :app:lintDebug` + the three shell/Python gates — **works, five
    separate invocations, nothing aggregates or enforces them** (H-41, H-09). `connectedDebugAndroidTest`
    additionally needs `bash scripts/push-model-for-tests.sh` with a 190 MB file at exactly
    190 085 487 bytes, which the script correctly refuses to substitute.

**Verdict: a fresh clone cannot build the project, and the blocker is step 2.** Steps 5, 6 and 9 are
each a ten-second README line away from being solved. Steps 3, 4, 7 and 8 work as documented, and
step 7's wrapper checksum is genuinely correct — this project's *build* is in better shape than its
*entry point*.

## Notes for the merge

**The shape of this axis.** Every other axis found defects in code that runs. This one mostly found
*absences* — no crash capture, no CI, no hooks, no lockfile, no export, no device register, no code
on `main`. Absences do not crash, so they do not show up in any of the other five readings; they
show up as the reason a defect stayed alive for three commits.

**Three things to carry up, in this order.**

1. **H-26 (Blocker) is the cheapest Blocker in the entire v2 register.** Ten lines in `Graph.init`,
   and `DEC-0014`'s own Consequences section already specifies the behaviour. It should be fixed in
   the same pass as D-03, which it sits beside: D-03 is "cloud chosen without a key runs local and
   says nothing"; H-26 is "a server configured under the old rule runs local and says nothing, with
   no wrong choice made at all." **They are the same defect class and should get the same fix
   shape** — a startup reconciliation that names what it changed.
2. **H-23 (Blocker) gates axis C's own recommendation.** C wants a signed release build installed and
   run — correctly. The moment that happens on a headset that already has notes, those notes are
   gone: different signer, forced uninstall, `allowBackup="false"`, no export. **A vault export must
   ship before the first signed install, not after.** This is the single ordering constraint this
   axis contributes to the fix plan.
3. **H-01 (Blocker) is what makes the other 188 findings discoverable on somebody else's headset.**
   Sixty lines, no dependency, no account. Until it exists, the second headset is a device the
   project cannot observe at all — and four of the v2 Blockers (A-02, A-03, B-01, D-02) fail on it in
   ways that produce no artifact anyone will ever read.

**Two claims other axes left open, now closed.**
- **C-19's wrapper checksum is correct** — verified byte-for-byte against Gradle's published sum
  (H-14). C-19's *dependency* half stands and is upgraded to High here (H-13).
- **The Meta Spatial SDK is at the newest version that exists** (0.14.0, 2026-09-11). **B-01's
  `dispatchEvent` behaviour cannot be fixed by upgrading** — there is nothing to upgrade to. That
  removes one option from B-01's fix space before anyone spends a day on it.

**One decision the register is missing.** DEC-0004 pins three versions for measured reasons, and
**the Kotlin reason has expired** (H-16): KSP is no longer Kotlin-paired, and 2.3.x exists. The
OkHttp reason **holds and is now verified** (H-17) but records one of its three constraints. A
successor entry should state both, and should state the seven *undocumented* pins (H-18) as what
they are — where things landed, not decisions. Per the register's own rule: append, do not edit.

**A note on sequencing.** H-08 (CI) is not the most severe finding here, but almost every other fix
in this report is worth less without it, and three of them (H-16's Kotlin bump, H-18's catalog sweep,
H-13's verification metadata) should not be attempted before it exists. E-17 reached the same
conclusion from the architecture side. Two axes arriving independently at *CI first* is worth more
than either saying it alone.
