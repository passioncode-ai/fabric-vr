## Release build and R8

**Measured for me:** `./gradlew :app:assembleRelease` exits 0, no `missing_rules.txt`,
`NotesDatabase_Impl` keeps its name, `NoteDao_Impl` → `h.i`, the `@Serializable` classes keep
`$$serializer`/`$Companion`, `WhisperNative` keeps its fully-qualified name, `com.meta.spatial.*` is
unrenamed, the three activities/app class keep their names, `SpatialPanelOwners` → `b.j`, and the
APK is unsigned and has never been on a device.

**Extending it, from `app/build/outputs/mapping/release/` and the APK:**

- **`NoteDao_Impl` → `h.i` is safe.** Room reaches the DAO impl only through code the annotation
  processor generated: `NotesDatabase_Impl` holds it as a field and constructs it with `new`. Nothing
  resolves it by name. The name that *must* survive is `NotesDatabase_Impl`, and
  `-keep class * extends androidx.room.RoomDatabase { <init>(); }` (`proguard-rules.pro:16`) is what
  keeps it — that rule is **load-bearing**. So is
  `-keep class ai.passioncode.fabricvr.stt.WhisperNative { *; }` (`:20`): the JNI symbols are spelled
  `Java_ai_passioncode_fabricvr_stt_WhisperNative_transcribe` in `fabricvr_whisper.cpp:60`, and a
  rename breaks the link at first call with `UnsatisfiedLinkError`, not at build time.
- **`SpatialPanelOwners` → `b.j` is safe.** Grep finds no string, resource or manifest reference to
  it; it reaches the composition through `CompositionLocalProvider` (`ImmersiveActivity.kt:108-111`),
  which is a compiled reference. The interfaces it implements are kept by androidx's own rules.
- **The `viewModel()` path survives.** The four screens create view models through the default
  factory, i.e. `Class.getDeclaredConstructor().newInstance()`. `configuration.txt:190-193` shows
  lifecycle-viewmodel's own consumer rule
  (`-keepclassmembers,allowobfuscation class * extends androidx.lifecycle.ViewModel { <init>(); }`)
  is in the effective configuration. The classes may be renamed — `viewModel()` uses the runtime
  class, never a name — so this is fine and needs **no** rule in `proguard-rules.pro`.
- **`R.style.Theme_FabricVR_Transparent` survives resource shrinking.** `isShrinkResources = true`
  plus a theme referenced only from Kotlin is the classic release-only breakage; `resources.txt:82`
  records `Marking style:Theme_FabricVR_Transparent:2131427340 reachable: referenced from
  in_memory_r8_base_classes0.dex`, and `:4550` confirms `reachable=true`. The SDK's own
  `SpatialSDKTransparentTheme` is kept only because it *matches a string pool constant* (`:4057`) —
  a heuristic, not a reference. That is the fragile one, and it belongs to the SDK.
- **`-keep class com.meta.spatial.** { *; }` (`:23`) is redundant, and it is not a size problem.**
  `configuration.txt:415-550` shows the SDK ships precise consumer rules of its own — `@DoNotStrip`,
  `@DoNotStripNative`, `@HoldsNativeHandle`, `ComponentBase` subclasses, `SpatialHostCallbacks`
  implementors, enums, `DataModel` members. The blanket rule keeps 1102 of the 4957 class mappings at
  their original names and defeats the `allowobfuscation` the SDK's own rules asked for. The cost is
  a fraction of a 3.93 MB `classes.dex` inside a **77.9 MB** APK whose weight is
  `libMetaSpatialSDK.so` (47.8 MB) and `libfabricvr_whisper.so` (15.0 MB) — so removing it is
  hygiene and shrink-correctness, worth perhaps 1–2 MB of dex, not a size win. Do not remove it
  blind: remove it, rebuild, and launch the Space, because the SDK's rules have never been exercised
  alone on this project.
- **What breaks first if this APK reaches a headset.** Nothing R8 did — the install does. The APK is
  unsigned, so `adb install` fails with `INSTALL_PARSE_FAILED_NO_CERTIFICATES` before a line of
  Kotlin runs (C-13). Sign it and the next thing to break is not R8 either: it is **C-02**, Back in
  the Space, which is reached on the first session and which no test in the tree covers. The first
  *R8-attributable* risk, if the blanket SDK keep is ever trimmed, is the Spatial SDK's reflective
  component registry — which is why the removal above must be a measurement and not a cleanup
  commit.
- **The whisper JNI `params.language` lifetime question: it is correct.** `std::string lang` is
  declared at `fabricvr_whisper.cpp:112`, `params.language` points at `lang.c_str()` at `:119`, and
  `whisper_full` is called at `:122` — same scope, the string is not modified between, and it is
  destroyed at `:146`. `whisper.h`'s `whisper_full_params` holds `const char * language` and the
  literal `"auto"` used when empty has static storage. No dangle. The defects in this file are C-07
  and C-08, not this.

## Not covered

- **Nothing was run on a device, and nothing was built.** Every runtime claim here is derived from
  source, the mapping/resources output, and the APK's contents. C-02, C-05, C-06 and C-12 are
  reasoned failure modes with a stated verification, not observations.
- The Gradle wrapper's `distributionSha256Sum` was **not** compared against the published checksum
  (no network). C-19 says so rather than claiming either result.
- `scripts/check-docs.sh` (24 KB) was read only at its header; the documentation gate is another
  axis's ground.
- Room schema/migration correctness, the notes data model, the vault's on-disk format, and
  `OpenRouterClient`'s streaming are outside axis C except where they touch the keystore or the
  network policy.
- Whether the Horizon OS shell actually routes a Back gesture to `Activity.onBackPressed()` in an
  immersive `AppSystemActivity` was not confirmed against Meta's documentation; C-02 stands on the
  absence of any dispatcher call in this repository, which is true either way.
- Thermal behaviour in the Space (C-10) rests on the project's own bench in
  `docs/modules/feature-stt.md`, which was taken **without** a scene rendering. The figure for "with
  the Space open" does not exist yet.
