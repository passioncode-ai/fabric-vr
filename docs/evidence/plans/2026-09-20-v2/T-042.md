## What is wrong, in the person's terms

`docs/ux/scenarios.md` is declared the source of truth for user-facing behaviour. It describes a
product with a hold-to-record gesture, a capture sheet with *Save* and *Discard*, a *New note*
button and a tag filter. None of those exist. A person handed this file and a headset cannot
perform step 3 of half of it.

Axis D walked all fifteen against the code. **Three hold, nine have drifted, three are broken** —
and the merge corrects one of the three that "hold" (see below), so the real score is **two hold,
ten drifted, three broken**.

## Where it is

## Correction to the finding

**Two corrections, both of which change what this task must do.**

**1. SCN-011 does not hold.** Axis D grades it *Holds* (`D.md`, SCN-011 section) with an aside that
"the root is `filesDir/vault` … the hint does not say". G-01 settles it: the vault is app-private
internal storage, `android:allowBackup="false"`, and
`grep -rn "ACTION_OPEN_DOCUMENT_TREE\|DocumentFile\|MANAGE_EXTERNAL\|getExternalFilesDir\|FileProvider\|ACTION_SEND" app core-* feature-*`
returns nothing. **The person cannot take the notes as files.** The scenario's title is the exact
thing the build cannot do. The merge's *Notes for the merge* already records this; D's own table
was never corrected. SCN-011 is **broken**, and the real score is two holding, ten drifted, three
broken.

**2. The plan's `Closes` range is wrong.** `docs/evidence/plans/2026-09-20-v2-plan.md:118` cites
`D (all), F-05…F-12`. Of that range, only **F-07** (screens.md `Coverage:` pointing at a deleted
file), **F-08** (SCR-01/SCR-03 element lists) and **F-09** (FLW-02 documenting the shipped shape as
*rejected*) are UX-document findings. **F-05** and **F-06** are `docs/modules/app.md`, **F-10** is
`docs/modules/feature-stt.md`, and **F-11**/**F-12** are `docs/DECISIONS.md` — all four belong to
T-045. Meanwhile the scenario findings that the range omits are **F-28** (four entry-point lines
still saying "(hold)"), **F-29** (three references to a deleted sheet), **F-35** (a duplicated
sentence) and **F-36** (the unusable `Status` column). The `Closes` line at the top of this spec is
the corrected set, and the plan row should be updated to match.

## The decision, and what was weighed

**Chosen: rewrite in place against the shipped build, per scenario, after the code that scenario
describes has landed — and change the meaning of `Status` so the column can carry information.**

**Alternatives considered:**

- ***Rewrite all fifteen now, ahead of WP-5.*** Rejected: five of them describe surfaces T-028 to
  T-032 are about to rebuild. Writing them twice is how F-28 happened — `732c92b` rewrote two
  scenario bodies and left every other reference standing.
- ***Delete the file and re-derive the scenarios from the code.*** Rejected: the scenarios encode
  the *job*, which the code does not. SCN-001's job ("write and keep a text note") is right even
  though nothing in the build does it; deleting it would delete the evidence that a notes app
  cannot write a note.
- ***Keep the drifted text and add a "as built" note per scenario,*** the convention a dated spec
  uses (F-39). Rejected here: a dated spec is a historical artefact and keeps its body; the
  scenarios are the **live contract**, read to decide what to build. A live contract with a drift
  table is two contracts.
- ***Mark every scenario `draft` and move on.*** Rejected: it makes the file honest and useless in
  the same stroke.

**The `Status` vocabulary, redefined, because today it is noise** (F-36 — thirteen say `validated`
for behaviour nobody has walked, and the two that say `draft` are the ones that shipped):

| Value | Means |
|---|---|
| `draft` | written, not yet true of any build |
| `built` | the code exists and the automated checks cover it; **nobody has walked it** |
| `validated` | a person walked it on a headset, on a named date, and it did what this file says |

`validated` becomes the same kind of claim as `verification.md`'s `Human` column: only a person can
write it, and it carries a date. That is the change that makes this file resist drifting again,
because `built` is an honest thing to write and `validated` stops being free.

  `docs/ux/lint.py`, `docs/OPEN_QUESTIONS.md`, one `DEC` row, one plan row.

  whole by the audit's own rule; SCN-011's correction is recorded here and in the merge, not by

  distinction is the whole reason the column is being redefined, and it will be lost the first
  time someone is generous with it.
- **Watch for:** `docs/ux/lint.py` is a gate. Extending it will make the current tree red until
  step 1 is complete — write the check and the fixes in one commit, or the gate blocks every other
  task in flight.
