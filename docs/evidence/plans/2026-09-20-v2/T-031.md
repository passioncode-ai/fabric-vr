# T-031 — The first run reaches a first dictation without reading a document

- **Severity:** Blocker
- **Work package:** WP-5 (the Today surface)
- **Closes:** D-05, G-17
- **Depends on:** T-028. Consumes **T-005** (the *Retry* fix), **T-008** (the provider refusal) and
  **T-009** (the permanently-denied path); does not re-implement any of them.
- **Needs a headset:** **yes**, and it is the only way this task can be finished — see
  *The observation that is the task*.
- **Estimated blast radius:** `VoiceViewModel` (one branch), `TodayScreen`'s status slot (one
  state), ~5 strings rewritten and ~4 added, 2 test files. No new screen, no dialog, no wizard.

## What is wrong, in the person's terms

Axis D traced it tap by tap on a clean headset — no permission, no model, no key,
`SttProvider.DEFAULT = LOCAL`, `WhisperModel.DEFAULT = SMALL` (190 MB). The trace, compressed,
with the source for each step:

| Tap | What they do | What happens | Where |
|---|---|---|---|
| — | launch | "Fabric VR", four unlabelled icons, a 128 dp **Record**, and one sentence: *"Nothing here yet. **Hold Record** and say something, **or start a note**."* | `TodayScreen.kt:127-138`, `:199-203`; `today_empty`, `strings.xml:102` |
| 1 | Record | no system prompt. The line becomes "Dictation needs the microphone." and the **button relabels itself** to *Allow the microphone* | `VoiceViewModel.kt:75-78`; `TodayScreen.kt:294-298`, `:335` |
| 2 | Allow the microphone | the OS dialog appears; they allow | `TodayScreen.kt:316` → `PermissionRequester` |
| — | — | **nothing visible happens.** `onPermissionResult` parks the machine in `Allowed`, which falls through `else -> Unit`, the warning disappears and the button silently says *Record* again | `VoiceViewModel.kt:143-151`; `TodayScreen.kt:306` |
| 3 | Record | permission passes; `modelMissing()` is true; a banner: *"The speech model isn't on this headset yet."* with **Download** and a ✕. **No model name, no "190 MB", no "text notes work meanwhile"** | `VoiceViewModel.kt:80-83`; `error_model_missing`, `core-common/.../strings.xml:10` |
| 4 | Download | honest and legible: a bar, "0 / 190 MB", a Cancel. **The first moment in the session they learn the size.** | `TodayScreen.kt:265-279` |
| — | download completes | `DownloadProgress.Done → VoiceState.Idle`. The bar vanishes. **Nothing says the model arrived or was verified.** Their only evidence that four minutes of waiting worked is the absence of the bar | `VoiceViewModel.kt:160` |
| 5 | Record | recording starts at last | |
| 6 | Stop recording | "Transcribing…", disabled. At the measured 1.31× real time a 40-second thought costs ~52 s with no progress, no elapsed count and no cancel | `TodayScreen.kt:333` |

**Six taps and a 190 MB download to the first dictation.** Three of the six (2, 4, 5) are the
contract's. Taps 1→2 and 4→5 are extra. **Tap 3 is pure waste** caused by the unhandled `Allowed`
state.

And the two sentences they read before the download are both wrong or empty of what matters. One
tells them to **hold** a button that toggles — the hold gesture was deleted by DEC-0010 — and to
"start a note", which has no control (A-01, fixed by T-028). The other omits the model, the size,
and the fact that the app is still useful without it.

D's own closing line is the fair summary: *"Nothing needs to be read from a document to reach a
first dictation — that much is true. But the route is discovered by pressing the same button five
times and watching what it says, which is discovery by repetition rather than by design."*

## The target, screen by screen and tap by tap

**Three taps, and every screen states its own next step.** The download is unavoidable; the taps
around it are not.

### Launch — nothing has been decided yet

Today's surface (after T-028), with the empty state rewritten:

> **Ничего ещё нет / Nothing here yet.**
> Press **Record** and speak. The first dictation downloads a 190 MB speech model — after that
> everything happens on this headset. You can also write a note without it.

Three facts, in the order a person needs them: what to press, what it will cost, and that there is
a way around it. The last clause is only honest **because T-028 put *New note* back** — before it,
it would have been the same lie `today_empty` tells today.

`today_empty` becomes `today_empty_first_run`, and there is a **second, shorter string** for the
empty state a person reaches by deleting their last note — they do not need the onboarding
paragraph again:

> **Nothing here yet.** Press Record and speak.

Choose between them on whether the model is present, not on a "has run before" flag: the model is
the thing the paragraph is about.

### Tap 1 — Record

No permission. **Do not relabel the button.** Today the button becomes *Allow the microphone*
(`TodayScreen.kt:335`), which is the extra tap: the person pressed Record and was answered with a
different button in the same place. Instead: **`start()` asks for the permission immediately**, so
the OS dialog appears on tap 1. `VoiceState.NeedsPermission` remains — it is the state shown after a
**refusal**, which is when an explanation is genuinely needed:

> The microphone is needed to dictate. **Ask again** · **Write a note instead**

The second action leads to T-028's *New note*. A person who does not want to grant the microphone
should not be left on a screen whose only control is one they have declined.

### Tap 2 — the OS dialog; they allow

**`Allowed` must start the recording.** `VoiceViewModel.onPermissionResult` (`:143-151`) currently
does:

```kotlin
_state.value = when {
    granted -> VoiceState.Allowed          // <- renders nothing, starts nothing
    permanent -> VoiceState.Failed(…)
    else -> VoiceState.NeedsPermission
}
```

SCN-013 step 3 says "the recording starts immediately, without re-pressing *Record*". Make it true:
`granted -> start()`. **Delete `VoiceState.Allowed` and the unused `state_allowed` string with it**
— B-05 offers "handle it or delete it" and there is nothing for it to mean once granting starts the
recording. Deleting it is what makes `RecordControl`'s `when` exhaustive (T-030 step 5), which is
what stops the next state from being silently dropped the same way.

If the model is missing, `start()` produces `Failed(ModelMissing)` — the person lands on the model
banner without a wasted tap. That is the whole of tap 3's removal.

### The model banner — say what it costs and what still works

`error_model_missing` today: *"The speech model isn't on this headset yet."* It becomes:

> **Speech needs a model — %1$s, %2$d MB.** It downloads once and then everything happens on this
> headset. You can write notes without it.
> **Download** · **Write a note instead** · ✕

The model name and size are already in hand: `modelStore().modelName` is passed to
`AppError.ModelMissing` at `VoiceViewModel.kt:81` and thrown away by the mapper
(`UiStateMapper.kt:21-22`, which takes no arguments). `WhisperModel` carries the size — the strings
`model_tiny` … `model_large_turbo` (`strings.xml:121-125`) state it. Use them; the banner is the
first place in the session where the cost is knowable and today it is the last.

`action_download_model` (`:35`) hard-codes "(190 MB)" in the string, which is wrong for four of the
five models. Make it a format argument. **That string is on T-032's stale list** — if T-032 has
landed, follow its registry rule instead of editing in place.

### Tap 3 — Download, and the arrival

The download itself is the one part of the flow D called honest. Two additions:

1. **A time estimate** — even "a few minutes on Wi-Fi" — because 190 MB with no ETA in a headset is
   an unbounded wait.
2. **Say it arrived.** `DownloadProgress.Done → VoiceState.Idle` (`VoiceViewModel.kt:160`) and the
   bar simply vanishes. Emit a confirmation through the same transient slot that carries "Saved,
   and copied": *"The speech model is ready. Press Record."* Four minutes of waiting must not end
   in an absence.

### Tap 3 (continued) — Record, speak, Stop

Recording works. **Transcription is the last silence**: "Transcribing…", disabled, no progress, no
elapsed count, no cancel, for ~52 s on a 40-second thought at the measured 1.31× real time.

**In scope here:** an elapsed counter in the status slot — `voice_seconds` (`strings.xml:103`)
already exists and is already used while recording (`TodayScreen.kt:258-262`), so it is the same
composable pointed at a different clock.

**Out of scope, and say so:** a real progress fraction (whisper.cpp would have to report it) and a
cancel (there is no cancellation path through `transcribe`, `VoiceViewModel.kt:130-141`). Both are
worth findings of their own; do not open them inside a first-run task.

### Done

The note commits itself, the clipboard is set, "Saved, and copied. Paste it anywhere." shows for
2.5 s (`TodayScreen.kt:102-108`, `:169-175`, `CONFIRMATION_MS` at `:460`). This part is right and
this task does not touch it — except that **T-025** may put a clipboard switch around it and
**T-030** owns the race in that `LaunchedEffect`.

## What is deliberately not built

- **No onboarding screens, no carousel, no "welcome".** The product's stated shape is one screen
  (`TodayScreen.kt:63-72`) and the fastest first dictation is the one where nothing stands between
  the person and the button. Every sentence above is rendered in a place that already exists.
- **No permission rationale dialog before the system dialog.** In a headset a dialog is another
  thing to aim at, and the reason is obvious from the button that was just pressed. The
  explanation belongs **after** a refusal, which is where it is put.
- **No "skip and set up later".** There is nothing to skip: the model banner already offers
  *Write a note instead*.
- **No first-run flag in `SecureSettings`.** The two empty states are chosen by whether the model is
  present, which is the thing they differ about. A flag would drift from reality the first time
  someone removed a model (`removeModel()`, `SettingsScreen.kt:192`).

## Correction to the finding

**D's trace says tap 2 is "Allow the microphone" and that the OS dialog appears then.** Correct,
and the reason is worth naming because the fix depends on it: `start()` does **not** request the
permission, it only sets `VoiceState.NeedsPermission` (`VoiceViewModel.kt:75-78`), and the request
lives in the composable's button handler (`TodayScreen.kt:316` → `onGrantPermission` →
`permissionRequester.requestRecordAudio`). So removing tap 1→2 means either calling the requester
from the first press, or having the view model signal "ask now". **The second is cleaner and it is
what this task should do** — the composable already holds the `PermissionRequester`
(`TodayScreen.kt:76`), so an event from the view model is one collector; putting permission policy
in the button's `when` is what produced the two-tap path in the first place.

**G-17 lists five dead strings to delete** — `state_keep_holding`, `state_release_to_finish`,
`state_allowed`, `action_hold_to_record`, `action_new_note`. **Four, not five.** `action_new_note`
gets a caller in **T-028** and must not be deleted; deleting it would silently re-open A-01. The
other four are genuinely dead — verified: `grep -rn "R.string.<name>" app/src/main/kotlin` returns
nothing for each. **They are T-032's to remove** (it owns the whole stale-string sweep); this task
only stops `state_allowed` being *reachable*, by deleting the state.

## The observation that is the task

**No test can close this task.** The finding is about a sequence a person performs on a device they
have never installed the app on, and every assertion above is about one step of it.

On a **factory-clean or freshly uninstalled** headset, with `adb logcat` running:

1. Install, launch. **Photograph the first screen.** Read the sentence aloud. Does it tell you what
   to press and what it will cost?
2. Press Record. **The OS dialog must appear on this press.** Allow.
3. **Recording must start without another press.** Note the wall-clock time.
4. Stop. Nothing is transcribable yet — the model banner appears. Does it name the model and the
   size? Does it offer a way to write instead?
5. Download. Note the elapsed time (the estimate is checked against this). When it finishes,
   **does anything say so?**
6. Press Record, speak one sentence, Stop. Note the elapsed seconds shown during transcription.
7. **Count the taps from launch to the first saved note.** Record the number in
   `docs/evidence/verification.md` against SCN-013 and D-05. **The target is three**, not counting
   the OS dialog's own button.

Do it **twice** — once by the person who wrote the change, once by someone who has not read this
spec. The second run is the only evidence that the route is discovered by design rather than by
having been told.

## Blast radius, and what NOT to touch

- **Touches:** `VoiceViewModel` (`onPermissionResult`, `start`, one sealed-interface member
  removed), `TodayScreen`'s status slot and button label, `UiStateMapper.ModelMissing`,
  ~9 strings, two test files.
- **Do not touch:** `VoiceViewModel.cancel()` / `retryLast()` / `dismissFailure()` — **T-005**.
  The provider resolution at `:80-83` — **T-008** fixes the cloud-user case (B-07) and changing the
  condition here would collide. The permanently-denied path at `:146-148` — **T-009**.
  `PermissionRequester` / `PanelActivity` — the requester works; what changes is when it is called.
  The download's own progress rendering — D called it the one honest part.
- **Watch for:** **`ImmersiveActivity` is not a `ComponentActivity`**, which is why
  `PermissionRequester` is hoisted the way it is. Raising an "ask now" event from the view model
  must work in both hosts, or the first run **in the Space** silently does nothing. Test it there,
  or state that the first run is a panel-only flow and that the Space assumes a granted microphone.
- **Watch for:** deleting `VoiceState.Allowed` changes an exhaustive `when` in every file that
  handles `VoiceState` — `TodayScreen`, `NoteEditorScreen` (`:110-116`), and the tests. The compiler
  finds them all; the review should confirm none was "fixed" with a new `else`.
