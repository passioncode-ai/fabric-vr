## What is wrong, in the person's terms

Every word the operator **writes** into this product is Russian. Every word it **says back** is
English. The product definition that describes it is itself written in Russian
(`docs/product/product-definition.md:1` — "Fabric VR — продуктовое определение (notes-first)"),
and the persona says so explicitly (`docs/ux/foundation.md:34-36`):

> Fluent in Russian and English, often mid-sentence in both.

The build addresses one half of that sentence.

This is not a blocker — this operator reads English — but it hides defects. An English *Retry*
under an English "The recording is kept." (A-03, T-005) reads as boilerplate. In Russian it would
have read as a lie on the first day.

## Correction to the finding

**G-09's counts are wrong, in both files, and the error is mechanical.** The finding says "152
strings in the app, 26 in core-common", and the assessment section derives "~178 strings" as the
translation's size from them.

`152` is `wc -l` on `app/src/main/res/values/strings.xml`, not its string count. The file has
**115** named resources. `core-common` has **24**, not 26 (its file is 34 lines).

The real size of a `values-ru` is **139 named resources, not 178** — about 22% less than the
finding's estimate. The direction of G-09 is right and nothing else in it moves; the cost figure in
Option B below is recomputed from the count above.

## The three answers

### Option A — stay English

Zero cost, today. The register records that the interface language is English by decision.

**What it costs later, and it is not nothing:**

- The class of defect G-09 names stays open: a wrong sentence in the operator's second language
  reads as boilerplate and survives another audit. A-03 and G-17 are both instances — the first
  sentence the product says to a person (`today_empty`) promises a deleted gesture and an
  unreachable control, and nobody noticed by reading it.
- Every string written from here on is written once, so the *option* on B stays cheap. Choosing A
  does not close B; it defers it.

### Option B — add `values-ru`

Two files, 139 resources. **Three things must land first, and none of them is optional:**

1. **T-032** — "every string a person reads is true of the build they are holding". Translating
   `action_hold_to_record` ("Hold to record", `strings.xml:30`, no Kotlin caller) into a gesture
   that does not exist is worse than leaving it English. G-17 names six such strings. Translate
   after the sweep, not before.
2. **B-22** — the three chat examples hard-coded in Kotlin (`ChatScreen.kt:84-88`) are not
   resources, so the assistant's first screen stays English however complete the translation is.
   **If T-033 cuts the assistant, this prerequisite disappears entirely** — which is one more
   reason to answer T-033 first.
3. **G-20** — `settings_vault_out_of_sync` (`strings.xml:88-91`) declares only `one` and `other`.
   Russian needs four: `one` (1, 21, 31 — заметка), `few` (2–4 — заметки), `many` (5–20, 0 —
   заметок), `other`. The `values` file stays as it is; `values-ru` declares all four. This is the
   only resource in either file needing structural work before translation.

**Cost:** one working day for 139 resources including a copy pass, plus the three prerequisites
above (T-032 is already scheduled; B-22 is minutes; G-20 is minutes).

**Who maintains it, and this is the real cost.** Every new string becomes two entries, forever. The
mechanism that makes that survivable is a gate, not a discipline: enable
`lint --check MissingTranslation` as an error (not a warning) and run it in CI under T-002. Without
that, `values-ru` decays into a partial translation, which is the worst of the three states — a
screen half in each language.

**Who writes it.** The operator. An agent can draft, but the register that says the copy is right
is the operator's signature, and there is nobody else on the project who can give it.

**What the copywriting rule requires, and the project does not have.** Any text a user of the
product reads goes through the brand pack first — `docs/brand/voice.md`, `terminology.md`,
`facts.md`. **This project has no brand pack.** Carry-over row 1 records it, tracked as `B-035`,
and `2f91df7`'s own commit message re-states the violation: *"Written without the brand pack, which
this project does not have yet."* So Option B forks again:

- **B1** — run `/brand-init` first, produce the pack, then translate against it. The Russian copy
  is then the first text in this product with a declared voice, and the English is retro-fitted to
  it. Adds roughly half a day and closes `B-035`.
- **B2** — translate directly and **say so**, in the commit and in the register: the pack was
  skipped on request. The refusal phrase for this is *"no brand"* / *«без бренда»*, and it applies
  to work that would otherwise have crossed the boundary. Skipping silently is the one thing the
  rule forbids.

### Option C — follow the note language

Switch the interface locale to match the transcription language setting.

**Rejected, for three reasons:**

1. **The setting it would follow is `auto`.** `LANGUAGES` puts `auto` first
   (`SettingsScreen.kt:290`) and it is the default. Under `auto` the note language is whatever
   whisper detected for the last dictation, so the interface would change language when the person
   dictates one English sentence — which is precisely the persona's normal behaviour ("often
   mid-sentence in both").
2. **It doubles the test matrix without removing the translation.** `values-ru` still has to exist
   and still has to be maintained; C adds a runtime switch on top of B rather than replacing it.
   Android already has the mechanism for a per-app locale (`android:localeConfig` +
   `AppCompatDelegate.setApplicationLocales`, API 33+, and this app is `minSdk 34`), so if a
   per-app override is ever wanted it is a Settings row, not an inference.
3. **It confuses a data property with a preference.** The language a person dictates in is a fact
   about the note. The language they read the interface in is a preference about themselves. Tying
   the second to the first means the product guesses at something the person can simply be asked.

If a per-app language control is wanted, it is Option B plus one Settings row — and that row is a
`super-ux` question, not this one.

## Recommendation

**Option B1, sequenced after T-032 and T-033.**

Add `values-ru`, and run `/brand-init` before writing it. The cost is one day plus half a day for
the pack, the count is 139 rather than the 178 the finding assumed, and the two heaviest
prerequisites (the dead strings, the hard-coded chat examples) are already being removed by tasks
in this plan — so the cheapest moment to do this is immediately after WP-5, and it gets more
expensive every time a string is added.

The sequencing is the whole recommendation. Translating now means translating strings that T-032 is
about to delete and a screen that T-033 may cut.

## Decomposition — none; the decision closed the task

**If A:** the task is one `DEC` row stating that the interface is English for v1, with the
revisit condition (a second Russian-speaking user, or the operator asking for it). No code.

**If B:**

1. `DEC` row: the interface ships in Russian and English; `values` is the source of truth and
   `values-ru` is generated from it by a person, never by a machine; `MissingTranslation` is an
   error. Read `docs/DECISIONS.md:7` for the free id at the time of writing.
2. **Prerequisite sweep** — confirm T-032 has landed and `grep -rn "R.string.action_hold_to_record"
   app/src/main/kotlin` is empty. Confirm B-22 is resolved or T-033 cut the screen.
3. `app/src/main/res/values/strings.xml:88-91` — nothing changes here. `values-ru/strings.xml`
   declares `one`, `few`, `many`, `other` for `settings_vault_out_of_sync`.
4. Create `app/src/main/res/values-ru/strings.xml` (115) and
   `core-common/src/main/res/values-ru/strings.xml` (24).
5. **Every format string keeps its placeholder order.** All of them are positional (`%1$s`,
   `%1$d / %2$d`), so word order is the translator's to choose — but `%1$s` must still refer to the
   same argument. `lint --check StringFormatInvalid,StringFormatMatches` catches the mechanical
   half.
6. Turn `MissingTranslation` and `ImpliedQuantity` into errors in the `lint` block of
   `app/build.gradle.kts` and `core-common/build.gradle.kts`, and add `lintDebug` to CI (T-002).
7. Verify on the headset (below).

## Blast radius, and what NOT to touch

- **Touches (B):** two new `values-ru` files; the `lint` block in two modules; one CI step; one
  `DEC` row.
- **Do not touch:** the English `values/strings.xml` files — they are the source and their
  identifiers must not move, or every reference in `docs/` and every `grep` in this plan's other
  specs breaks at once. Do not reorder them either; a diff of a translation against a reordered
  source is unreviewable.
- **Do not translate `docs/`.** The product definition is already Russian, the module documents and
  registers are English, and that split is deliberate: the registers are read by agents.
- **Watch for:** `core-common`'s strings are the error vocabulary (`UiStateMapper`). A mistranslated
  error is worse than an English one, because the person cannot search for it. Translate those last
  and with the most care.
