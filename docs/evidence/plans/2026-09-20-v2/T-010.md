# T-010 — A URL's userinfo is not its host

- **Severity:** Blocker
- **Work package:** WP-1 (stop the data loss)
- **Closes:** C-01
- **Depends on:** nothing
- **Needs a headset:** no. Everything here is decidable on the JVM, and most of it already has
  been — see *Measured*.
- **Estimated blast radius:** 1 function rewritten (~30 lines), 1 module gains one dependency,
  1 test file extended from 5 to ~14 cases. No caller signature changes.

## What is wrong, in the person's terms

Someone gives the operator an address to paste into *Settings → Cloud service*:

```
http://192.168.0.5:8080@evil.invalid/
```

It reads like a LAN address — an IP, a port. The app's own hint under the field says
*"https anywhere, or http to a device on your own network"*, and the app agrees: the policy says
this is reachable, the field saves, no warning appears.

**Every dictation from then on is uploaded to `evil.invalid`, over plain `http`, with
`Authorization: Bearer <the cloud key>` in the headers and a WAV of the person's voice in the
body.** RFC 3986 puts the userinfo before the `@`; everything before it is a username and a
password, and the host is what follows. OkHttp knows that. `NetworkPolicy` does not.

`CloudTranscriptionClient`'s own KDoc says, at `feature-stt/.../CloudTranscriptionClient.kt:32-34`:

> The recording leaves the device here, so the constructor refuses an endpoint the network policy
> will not allow… **A microphone recording sent in the clear is the failure this class must not
> have.**

It has it.

## Where it is

`core-common/src/main/kotlin/ai/passioncode/fabricvr/common/NetworkPolicy.kt:25-44`, whole
function:

```kotlin
    fun requireReachable(url: String): Result<String> {
        val trimmed = url.trim()
        val scheme = trimmed.substringBefore("://", missingDelimiterValue = "").lowercase()
        if (scheme != "http" && scheme != "https") {
            return Result.failure(InsecureUrlException(AppError.InsecureUrl(url)))
        }
        val hostAndRest = trimmed.substringAfter("://")
        if (hostAndRest.isBlank()) {
            return Result.failure(InsecureUrlException(AppError.InsecureUrl(url)))
        }
        val host = hostAndRest.substringBefore('/').substringBefore(':')
        if (host.isBlank() || host.contains(' ')) {
            return Result.failure(InsecureUrlException(AppError.InsecureUrl(url)))
        }
        return if (scheme == "https" || isPrivateHost(host)) {
            Result.success(trimmed)
        } else {
            Result.failure(InsecureUrlException(AppError.InsecureUrl(url)))
        }
    }
```

Line 35 is the defect. `substringBefore('/')` then `substringBefore(':')` on
`192.168.0.5:8080@evil.invalid` yields `192.168.0.5`, which `isPrivateHost` (`:18-19`)
matches.

Three callers, all of which delegate rather than duplicating — which is the good news, because
fixing one function fixes all three:

- `feature-stt/.../CloudTranscriptionClient.kt:45-47` — the constructor, throwing
  `SttException(AppError.InsecureUrl)`.
- `feature-stt/.../RemoteWhisperClient.kt:41-44` — `validateBaseUrl`, whose comment reads
  "`DEC-0005`, delegated to the one policy both HTTP clients obey".
- `feature-assistant/.../OpenRouterClient.kt:37-41` — the `init` block.

(F-12 notes DEC-0005 still says there are *two* call sites. There are three. Not this task's to
correct — T-045's — but the third is `CloudTranscriptionClient`, the one that sends the voice.)

## Correction to the finding

**C-01's core claim is exactly right** and its two named attack strings both reproduce. Three
corrections, all of which change what a developer should write.

**1. `http://127.0.0.1@evil.invalid/` is already refused, so it is not a failing test.** C-01's *Verify
by* says: *"Add these two URLs plus `http://127.0.0.1@evil.invalid/` to `NetworkPolicyTest`"* — as if
all three currently pass. They do not. The escape needs a **colon inside the userinfo**: with no
colon, `substringBefore(':')` leaves `127.0.0.1@evil.invalid` whole, and the regex is anchored (`$`),
so it does not match. Only the `<private-ip>:<anything>@<host>` shape gets through. Keep the
string as a regression test — it must *stay* refused — but do not present it as one of the ones
to watch fail, or the developer will conclude the fix is not needed.

**2. "already on the classpath in both modules" is false for the module that matters.** C-01
proposes `okhttp3.HttpUrl.parse(url)`. `NetworkPolicy` lives in `:core-common`, and
`core-common/build.gradle.kts:30-43` declares `core-ktx`, the Compose BOM, three Compose `api`
lines, `coroutines-android`, and the test deps. **No okhttp.** Using `HttpUrl` means adding a
dependency to the module the audit describes as a design-system module (`E.md:66-70`). That is a
real cost and this spec pays it deliberately, with the reasoning below.

**3. The fix has four more edges than C-01 names**, all measured above: an unbracketed IPv6 host
coming back from `HttpUrl`, a trailing dot surviving canonicalisation, `%2e` decoding into one,
and leading-zero octets. None is an escape today, and three of the four are currently fail-closed
— but a rewrite that does not decide about them decides about them by accident.

## The decision, and what was weighed

**Chosen: parse with OkHttp's own parser, reject any URL carrying userinfo, and test the parsed
host — all three, not one of them.**

```kotlin
    fun requireReachable(url: String): Result<String> {
        val trimmed = url.trim()
        fun refuse() = Result.failure<String>(InsecureUrlException(AppError.InsecureUrl(url)))

        // The transport's own parser, on purpose: the defect was a parser differential. This used
        // to read the host with substringBefore('/').substringBefore(':'), which takes the
        // USERINFO of `http://192.168.0.5:8080@evil.invalid/` for the host — so the policy
        // said "a device on your own network" while OkHttp resolved a public one and sent the
        // cloud Bearer key and a WAV of the person's voice to it in the clear.
        val parsed = trimmed.toHttpUrlOrNull() ?: return refuse()

        // Nothing this app talks to authenticates in the URL — the cloud client sends
        // `Authorization: Bearer`, the whisper server sends nothing. Credentials in a settings
        // field are a mistake or an attack, and refusing the whole category is cheaper than
        // trusting one parser forever.
        if (parsed.username.isNotEmpty() || parsed.password.isNotEmpty()) return refuse()

        val host = parsed.host.removeSuffix(".")          // one trailing dot is the DNS root
        if (host.isEmpty() || host.endsWith(".")) return refuse()

        return if (parsed.scheme == "https" || isPrivateHost(host)) Result.success(trimmed)
        else refuse()
    }
```

`isPrivateHost` gains one guard and keeps its shape:

```kotlin
    /** True for a host the app may reach over plain http. */
    fun isPrivateHost(host: String): Boolean {
        // An octet with a leading zero is read as octal by the resolver — 010.0.0.1 is 8.0.0.1 —
        // so a form whose meaning depends on who parses it is refused rather than interpreted.
        if (host.split('.').any { it.length > 1 && it.startsWith("0") && it.all(Char::isDigit) }) return false
        return PRIVATE_IPV4.matches(host) || host == "localhost" || host.endsWith(".local")
    }
```

### Why both, and not one

**Parse-and-read-`.host`** removes the *root cause*: the app decided with one parser and sent with
another. Any fix that keeps a hand-rolled parser keeps a differential, and the differential is the
bug class — not the `@`.

**Rejecting userinfo outright** removes the *category*. It is the belt to the parser's braces, and
it costs one condition. C-01 offers the two as alternatives; they are not exclusive, and for the
single function that decides whether a recording of a person's voice leaves the device in the
clear, defence in depth is the correct posture.

### Weighing the two, as C-01 asks

**Reject `@` outright, alone, with the string parsing kept.** Two lines, no dependency.

- It closes the two known strings.
- It closes nothing else. `substringBefore(':')` still mangles `[::1]:8080` into `[`; the app
  would still be deciding with a different parser than it sends with; and the next differential —
  a backslash, a `#`, a percent-encoding — is found the same way this one was.
- It also refuses `http://user:pass@192.168.1.20:8080/`, a LAN whisper-server behind basic auth.
  Nobody uses that today (both clients authenticate by header), so this is a cost only in
  principle — and the chosen fix refuses it too, deliberately.

**`HttpUrl.parse` / `toHttpUrlOrNull`, alone.**

- Removes the differential, which is the important half.
- Leaves a URL with userinfo *allowed* whenever the host itself is private:
  `http://admin:hunter2@192.168.1.20/` would pass. That is arguably correct — the host really is
  private — but it means a credential travels in a field the app logs nowhere and shows in plain
  text, and it is one behaviour change in OkHttp away from mattering again.

**Rejected outright: `java.net.URI`** (the no-dependency version of the chosen fix). Measured, it
disagrees with OkHttp in four places at once: `URI("http://[::1]:8080/").host` is `[::1]` where
`HttpUrl` gives `::1`; `URI("http://192.168.1.20./").host` is **null** where `HttpUrl` gives
`192.168.1.20.`; `URI` throws on `http://192.168.1.20\@evil.invalid/` where `HttpUrl` accepts
it; `URI` gives a null host for `0x7f.0.0.1` where `HttpUrl` returns it verbatim. Every one of
those is a fresh differential between what we check and what we send. **Using a second parser to
fix a two-parser bug is the wrong shape**, even though every one of those differentials happens to
fail closed today.

### The dependency cost, paid deliberately

`core-common/build.gradle.kts` gains:

```kotlin
    implementation(libs.okhttp)
```

`implementation`, not `api`, so it does not leak onto consumers' compile classpaths.
`:core-common` is depended on by every other module and depends on nothing but AndroidX, so there
is no cycle; `:feature-stt` and `:feature-assistant` already resolve `okhttp 4.12.0` and it is
DEC-0004-pinned (H-17 verified the pin's reason still holds). The APK gains nothing — the library
is already in it.

**The honest objection:** `:core-common` is described as "design tokens and theme, the `AppError`
taxonomy, the message mapper, secure settings" (`README.md:126`), and a networking library is out
of character. The alternative — move `NetworkPolicy` to a module that already has okhttp — does
not work: `:feature-assistant` and `:feature-stt` both use it and neither depends on the other
(`E.md:47-52`, and that acyclic shape is "the single best structural property this codebase has").
A new `:core-net` module for one object is 110 lines of build file (E-19) for one file. **Add the
dependency, and write the reason in `core-common/build.gradle.kts` beside it.**

### The three edges this fix decides, and one it hands to the operator

| Edge | Decision | Why |
|---|---|---|
| **trailing dot** (`192.168.1.20.`, `whisper.local.`) | strip exactly one, then test | It is the DNS root label and the same host. Today it is refused — fail-closed but wrong, and it refuses `whisper.local.` which is a legitimate mDNS form. Stripping is safe in both directions: `evil.invalid.` → `evil.invalid` is still public and still refused. A *second* trailing dot is malformed and stays refused. |
| **leading-zero octets** (`192.168.01.20`, `010.0.0.1`) | refuse | The resolver reads them as octal (measured: `192.168.01.20` → `192.168.1.20`). No escape exists today because the regex anchors on literal `10.`/`172.`/`192.168.`, but a form whose meaning depends on who parses it has no place in this function. |
| **integer and hex hosts** (the decimal form of 127.0.0.1 (`0x7f000001`) → 127.0.0.1) | refuse — unchanged | Already fail-closed. Pin it with a test so it stays deliberate rather than accidental. |
| **IPv6** (`::1`, `fd00::1`, `fe80::…`) | refuse over http — unchanged, **and this is the operator's to revisit** | `PRIVATE_IPV4` is IPv4-only, so an IPv6 loopback or a ULA is refused over cleartext. Fail-closed, and it refuses a genuinely private address. Widening it means allowing cleartext to `::1`, `fc00::/7` and `fe80::/10` — a real extension of what leaves the device unencrypted. **Nobody should make that call inside a security fix.** The options: leave it refused (nothing breaks today; an IPv6-only LAN whisper-server is unreachable) or add the three ranges (parity with IPv4, more cleartext surface). Put it on the board; pin the current refusal with a test either way, so the next reader can tell a decision from an oversight. |

### What `requireReachable` returns

**Unchanged: the trimmed original string.** Not `parsed.toString()`.

This matters and is easy to get wrong. `HttpUrl.toString()` canonicalises — it appends a `/` to an
empty path, drops a default port, lowercases the host. `http://192.168.1.20:80/x` becomes
`http://192.168.1.20/x`. All three callers build request URLs from the returned value
(`CloudTranscriptionClient.kt:45-47` does `.trimEnd('/')` and then appends a route), so returning
a canonicalised string would change what is actually requested, in a task whose whole subject is
not changing what is requested. **Parse to decide; return what you were given.** There is no
differential in doing so, because OkHttp will parse the same string the same way when it sends it.

```kotlin
        // Measured 2026-09-20: this one did NOT get through the old parser, because
        // substringBefore(':') left `127.0.0.1@evil.invalid` whole and the regex is anchored.
        assertFalse(allowed("http://127.0.0.1@evil.invalid/"))
        assertFalse(allowed("http://localhost@evil.invalid/"))
        assertFalse(allowed("http://whisper.local@evil.invalid/"))
    }

    @Test fun `a trailing dot is the same host`() {
        assertTrue(allowed("http://192.168.1.20./"))     // refused today — a fix, not a regression
        assertTrue(allowed("http://whisper.local./"))
        assertFalse(allowed("http://evil.invalid./"))
        assertFalse(allowed("http://192.168.1.20../"))
    }

    @Test fun `an octet with a leading zero is refused rather than interpreted`() {
        // InetAddress reads 192.168.01.20 as 192.168.1.20 and 010.0.0.1 as 8.0.0.1.
        assertFalse(allowed("http://192.168.01.20/"))    // ALLOWED today
        assertFalse(allowed("http://010.0.0.1/"))
    }

    @Test fun `a host that is not a dotted quad is refused over cleartext`() {
        assertFalse(allowed("http://2130706433/"))       // InetAddress: 127.0.0.1
        assertFalse(allowed("http://0x7f.0.0.1/"))
    }

    @Test fun `an ipv6 literal is refused over cleartext, deliberately`() {
        // PRIVATE_IPV4 is IPv4 only. ::1 and fd00::/8 are genuinely private and are still refused;
        // widening the cleartext allowance to IPv6 is an operator decision, not an oversight. See
        // T-010's board row.
        assertFalse(allowed("http://[::1]:8080/"))
        assertFalse(allowed("http://[fd00::1]:8080/"))
        assertTrue(allowed("https://[::1]:8443/"))
    }

    @Test fun `a backslash does not smuggle a host past the check`() {
        assertFalse(allowed("http://evil.invalid\\@192.168.1.20/"))
        // OkHttp reads this one's host as 192.168.1.20 — private, and therefore allowed. Asserted
        // so that a change in how the parser treats '\' is a failing test rather than a surprise.
        assertTrue(allowed("http://192.168.1.20\\@evil.invalid/"))
    }

    @Test fun `the url that comes back is the one that went in`() {
        // Not the canonicalised form: every caller builds a request from this value, and
        // HttpUrl.toString() drops default ports and appends a path.
        assertEquals("http://192.168.1.20:8080", NetworkPolicy.requireReachable("  http://192.168.1.20:8080  ").getOrNull())
    }
```

## Blast radius, and what NOT to touch

- **Touches:** `core-common/.../NetworkPolicy.kt` (one function rewritten, one guard added),
  `core-common/build.gradle.kts` (+1 `implementation`),
  `core-common/src/test/.../NetworkPolicyTest.kt` (+9 tests).
- **Do not touch:**
  - `CloudTranscriptionClient`, `RemoteWhisperClient`, `OpenRouterClient`. All three delegate
    correctly. The thing to verify about them is that nothing changed, not that something did.
  - `PRIVATE_IPV4`'s ranges. Widening or narrowing the *policy* is DEC-0005's and a product
    decision (step 5).
  - `AppError.InsecureUrl` and its string — the taxonomy is right.
  - `Graph.sttEngine()`'s handling of a refused endpoint — **T-008**. That task turns the refusal
    into a message the person can act on; this one decides what counts as a refusal. Adjacent, and
    separate on purpose: merging them would put a security fix and a routing rewrite in one diff.
  - `android:usesCleartextTraffic="true"` in the manifest (`AndroidManifest.xml:30`) and the
    absence of a `network_security_config.xml`. The platform-level allowance is what makes the
    in-code policy the only line of defence; tightening it is a separate change with its own
    device risk.
- **Watch for:**
  - `okhttp3.HttpUrl.parse(String)` is the Java-style static; from Kotlin the idiomatic form is
    `String.toHttpUrlOrNull()` (`okhttp3.HttpUrl.Companion.toHttpUrlOrNull`). They behave
    identically; use the extension and import it explicitly.
  - `HttpUrl` returns IPv6 hosts **without** brackets. Any future IPv6 matching must not expect
    them — that is exactly the differential that would recreate this bug in the other direction.
  - `:core-common` has instrumented tests (`SecureSettingsTest`, `UiStringsTest`). Adding a
    dependency changes the module's `androidTest` classpath too; confirm the module still
    assembles for `connectedAndroidTest` even though those tests cannot run in CI.
  - `lintDebug` may now warn about an unused dependency if the implementer inlines the parse
    somewhere unexpected. It should not; if it does, the parse is in the wrong place.
