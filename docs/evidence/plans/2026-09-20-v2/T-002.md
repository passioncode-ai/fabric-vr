# T-002 — CI: the four gates and the JVM suite on every push

- **Severity:** High
- **Work package:** WP-0 (honest build)
- **Closes:** H-08, C-14, E-17, H-09
- **Depends on:** T-001 (the suite must be green before a gate is pointed at it, or CI starts red
  and is switched off in a week)
- **Needs a headset:** no — and the point of the task is to say, in the workflow itself, exactly
  what it therefore cannot see.
- **Estimated blast radius:** 2 new files (`.github/workflows/ci.yml`, `scripts/check-all.sh`),
  1 decision amended, 1 README section corrected. No source changes.

## The decision, and what was weighed

**Chosen: one workflow file, two jobs, no matrix, no emulator, no coverage gate, and one shell
script that both CI and a person run so the two cannot diverge.**

### Why two jobs and not one

`checks` is cheap and must run on every push to every branch, because its whole value is latency
— the secret scan and the doc gate cost seconds and catch the classes above. `release` pays for
the Android NDK and an R8 pass; it belongs on the working branch and `main` only.

**Alternatives considered:**

- *One job.* Rejected: a push to a scratch branch would pay four minutes of NDK for a doc typo, and
  the first person to feel that turns the workflow off.
- *Only on `pull_request`.* Rejected: this project does not use pull requests — 37 commits went
  straight onto `feat/v1-notes-core`. A PR-only trigger would never fire.
- *A self-hosted runner with a headset attached.* Rejected, with H's reasoning (H.md:162): for two
  devices the cost of maintaining it exceeds the cost of a person putting the headset on and
  pasting a line into the ledger.
- *An x86 emulator so `connectedAndroidTest` "runs".* Rejected emphatically. It would go green on a
  platform this app does not ship to — `abiFilters += "arm64-v8a"` (`app/build.gradle.kts:22`)
  means the native library is not even in that APK — and a green on the wrong platform is worse
  than no signal. The workflow says this in a comment, so nobody adds it later thinking it was an
  oversight.
- *A coverage threshold.* Rejected: the suite is young and a threshold would be a number nobody
  chose.
- *Dependabot / a nightly version bump.* Rejected until H-13's `verification-metadata.xml` exists —
  otherwise every bump is an unverified resolution.

### Which JDK — and this one is close

`app/build.gradle.kts:57-64` sets `sourceCompatibility`/`targetCompatibility`/`jvmTarget` to 17.
That is the *bytecode* target and it is satisfied by any JDK ≥ 17. The question is which JDK
*Gradle itself* runs on, and H-37 records that nothing in this repository enforces one: the whole
mechanism is a sentence in the README telling the reader to `export JAVA_HOME` to Android Studio's
JBR, which on this machine is **openjdk 21.0.10**.

**Chosen: `temurin` 21 in CI**, because CI must reproduce the machine that produced the evidence,
and that machine is on 21. Pinning CI to 17 would mean every failure has two candidate causes.

**This is the half that is the operator's, not the developer's.** H-37 proposes a real fix — a
foojay toolchain resolver plus `jvmToolchain(17)` — which would make the JDK a property of the
build rather than of the machine, and would make the CI pin redundant. That is a build-system
change with its own risk and is **not in this task**. Until it lands, CI and the README must name
the same version. If the operator would rather standardise on 17, change both in one commit; do
not change one.

### What CI cannot catch, and what replaces it

Everything that needs a headset:

- `ImmersiveLaunchTest`, `PanelSmokeTest` — Horizon OS and the Spatial SDK runtime.
- `WhisperEngineTest`, `WhisperBenchmarkTest` — arm64 plus a 190 MB model pushed to
  `/data/local/tmp` by `scripts/push-model-for-tests.sh`.
- `SecureSettingsTest` — a real AndroidKeyStore.
- `UiStringsTest` — a real resource table. (Arguably Robolectric-able; not in this task.)
- `ModelDownloadReachabilityTest` — Hugging Face's live CDN. It is the right test for the defect it
  guards (`4bddfcc`) and it will go red the day the vendor moves, which is the point — but that
  makes it a **network-dependent** test, and putting it in a required CI job would make the build
  fail on somebody else's outage. It stays instrumented.

And everything the v2 merge listed as unsettleable: on-head legibility, hit rate at real distance,
transcription quality, whether the IME appears for a Spatial panel at all.

**The honest substitute is the ledger check (H-10).** `docs/evidence/device-gate.md` is created by
T-001. This task adds the check: a push that changes anything under `*/src/androidTest/**` fails
unless the newest ledger row's commit is an ancestor of `HEAD`. It does not run the tests. It makes
it impossible to ship a change to them while pretending they ran, which is exactly F-03.

### DEC-0001's false clause

DEC-0001 is Accepted and append-only; its body may not be edited (`docs/DECISIONS.md:37-39` — "add
a new entry, edit **only the status line** of the old one"). So: a new decision records that the
gate's home is CI rather than a pre-commit hook, marked `Contradicts: DEC-0001`, and DEC-0001's
status line gains the annotation `check-docs.sh` section 6 then enforces. **Reserve the id by
reading `Next free ID` (currently the register's next free id) immediately before writing, not from this document** —
twelve other DEC rows are queued by F.md and the allocator moves.

A hook was weighed and lost: `--no-verify` skips it, `.git/hooks` does not survive a clone, and a
`core.hooksPath` pointed at a tracked `.githooks/` still needs one manual `git config` per clone.
CI cannot be skipped and is one file.

## Decomposition

**Step 1 — `scripts/check-all.sh`, first, because CI calls it.** One script, five checks, fail on
the first:

```bash
#!/usr/bin/env bash
# check-all.sh — every gate this project has, in one command.
#
# CI calls this file and nothing else, so "green locally" and "green in CI" cannot
# mean different sets of checks. Adding a gate means adding it HERE.
# EXIT CODE IS THE OUTPUT: non-zero on the first failure.
set -eu
bash scripts/check-secrets.sh
bash scripts/check-docs.sh
python3 docs/ux/lint.py
./gradlew --no-daemon testDebugUnitTest
./gradlew --no-daemon :app:lintDebug
echo "OK: all gates"
```

Order matters: the two shell gates and the Python linter cost about eight seconds between them, so
a documentation failure reports in eight seconds rather than after a six-minute Gradle run.

**Step 2 — `.github/workflows/ci.yml`.**

```yaml
# The gates, on every push. This file exists because three defects in this project
# survived for an unknown period each, and every one of them is caught by a command
# that already existed and that nobody ran:
#   - check-secrets.sh greped nothing for an unknown period (f7d656d)
#   - PanelSmokeTest was red for three commits (F-02/F-03)
#   - :app:assembleRelease had never been attempted at all (C-13)
#
# WHAT THIS CANNOT CATCH, stated so nobody adds it later thinking it was forgotten:
# every instrumented test. They need arm64, Horizon OS, the Meta Spatial SDK runtime
# and a 190 MB model on the device. A hosted x86 emulator would run NONE of them —
# the APK is arm64-only (app/build.gradle.kts:22) — and a green on a platform the app
# does not ship to is worse than no signal. The substitute is the device-gate ledger
# check in the `checks` job below.
name: ci

on:
  push:
  pull_request:

# A second push to the same branch cancels the first: the interesting answer is
# always about the newest commit.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive   # third_party/whisper.cpp; :feature-stt's CMake guard needs it
          fetch-depth: 0          # check-docs.sh section 9 resolves SHAs against history

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'      # matches the JBR this project is developed on (H-37)

      - uses: gradle/actions/setup-gradle@v4

      # The device-gate ledger (H-10). CI cannot run the instrumented suite; it can
      # refuse to let a change to that suite pass unrecorded.
      - name: instrumented changes must carry a device-gate row
        run: bash scripts/check-device-gate.sh

      - name: gates
        run: bash scripts/check-all.sh

  release:
    # The expensive job: the NDK, whisper.cpp for arm64, and an R8 pass. Working
    # branch and main only — a scratch branch should not pay four minutes for a typo.
    if: github.ref == 'refs/heads/main' || github.ref == 'refs/heads/feat/v1-notes-core'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'

      - uses: android-actions/setup-android@v3   # accepts the SDK licences (H-38)

      - uses: gradle/actions/setup-gradle@v4

      # The .cxx tree is what makes the second run cheap; without it every run
      # recompiles whisper.cpp for arm64 from scratch.
      - name: cache the native build
        uses: actions/cache@v4
        with:
          path: |
            feature-stt/.cxx
            feature-stt/build/intermediates/cxx
          key: cxx-${{ runner.os }}-${{ hashFiles('.gitmodules', 'feature-stt/src/main/cpp/**', 'feature-stt/build.gradle.kts') }}

      - name: assemble release
        run: ./gradlew --no-daemon :app:assembleRelease -PversionCode=${{ github.run_number }}

      # This APK is UNSIGNED: keystore.properties is untracked and absent on a runner,
      # so app/build.gradle.kts:48-54 takes the unsigned branch and logs that it did.
      # It proves R8, the NDK and the manifest merge — not signing, and not that any
      # headset will install it. Signing is T-039/T-037; publishing is T-041.
      - uses: actions/upload-artifact@v4
        with:
          name: app-release-unsigned-${{ github.run_number }}
          path: app/build/outputs/apk/release/*.apk
          if-no-files-found: error
```

**Step 3 — `scripts/check-device-gate.sh`.** Small, and it must be *measured* rather than
asserted:

```bash
#!/usr/bin/env bash
# A change to the instrumented suite must come with a run of it, or with a row that
# says it was not run and why. CI cannot run these tests; it can refuse to let a
# change to them pass unrecorded. That is exactly the failure F-03 recorded.
set -eu
LEDGER=docs/evidence/device-gate.md
BASE="${1:-origin/main}"
changed=$(git diff --name-only "$BASE"...HEAD -- '*/src/androidTest/**' || true)
[ -z "$changed" ] && { echo "ok: no instrumented sources changed"; exit 0; }
[ -f "$LEDGER" ] || { echo "ERR: $changed changed and $LEDGER does not exist"; exit 1; }
newest=$(grep -oE '\b[0-9a-f]{7,40}\b' "$LEDGER" | tail -1)
if git merge-base --is-ancestor "$newest" HEAD 2>/dev/null; then
  echo "ok: newest device-gate row ($newest) is an ancestor of HEAD"
else
  echo "ERR: instrumented sources changed and the newest device-gate row ($newest) is not an ancestor of HEAD"
  exit 1
fi
```

**Watch it fail before believing it** — that is this repository's own standing instruction
(`F.md:217`): plant a change in `app/src/androidTest/` with no ledger row and confirm exit 1.

**Step 4 — give `check-docs.sh` a canary (H-12).** `check-secrets.sh:27-34` has one, and it exists
because that gate was found greping nothing. `check-docs.sh` is 24 KB across eleven sections and
has none: a section whose input is missing prints `dormant:` and passes, and its own header
(`scripts/check-docs.sh:22-27`) records that a fully populated ADR register once sat behind eight
green `dormant` lines. **CI turning a blind gate green every four minutes is worse than a blind
gate nobody runs.** Minimum here: a self-test for section 1 (dangling links) and section 2
(undefined ids) — plant one of each into a temp copy of `DOCS_DIR`, assert the script exits
non-zero, then run for real. Per-section canaries for the other nine are their own task; say so
in the commit rather than pretending it is done.

**Step 5 — the decision.** Read `docs/DECISIONS.md`'s `Next free ID` line, reserve it, write an
entry: *the documentation gate's home is CI, not a pre-commit hook*, with
`Contradicts: DEC-0001` and a `Consequences / affects:` line naming `docs/DOCMAP.md` and
`README.md`. Then annotate DEC-0001's **status line only**. `check-docs.sh` section 6 enforces the
annotation, so this is self-checking once written.

**Step 6 — `docs/DOCMAP.md`'s Gates table.** It lists one gate (F-26); there are five. Add
`scripts/check-all.sh` as the aggregate with `When: every push (CI) and before a commit`, and list
the four it calls.

**Step 7 — `README.md:111-119`.** Replace the five loose commands with `bash scripts/check-all.sh`
plus the list of what it runs, and correct `115` to `122`. Do not restate the count anywhere else —
F-22, F-23 and F-34 are all the same number written down four times.

## What this costs

Estimated, not measured — the numbers below come from the job shapes, not from a run, and the
first green run replaces them:

| Job | Cold | Warm |
|---|---|---|
| `checks` — 3 gates + `testDebugUnitTest` + `lintDebug` | ~5–7 min (Gradle distribution, ~120 artifacts, Robolectric's first SDK download) | ~90 s |
| `release` — SDK licences, NDK 27.2.12479018, CMake, whisper.cpp arm64, R8 | ~10–14 min | ~4 min |

GitHub's free tier for a private repository is 2 000 runner-minutes a month. At the observed rate
(37 commits in two days, so call it 20 pushes a day at the peak) `checks` alone is ~30 min/day
warm; `release` fires on the working branch only. Comfortably inside the allowance, and zero if
`main` is ever made public.

**One thing to measure on the first run, because it changes the shape:** whether
`testDebugUnitTest` drags the CMake build in. If `:feature-stt`'s external native build is a
dependency of its unit-test variant, `checks` inherits the NDK cost and should get the same cache
as `release`. Settle it with `./gradlew :feature-stt:testDebugUnitTest --dry-run | grep -i
externalNativeBuild` before writing the cache into `checks`, and record the answer in the
workflow's comment. Do not assume either way.

## Tests

CI is itself the test, so what must be watched is the *gate failing*:

| Check | How to watch it fail first | Asserts |
|---|---|---|
| `scripts/check-all.sh` | break one JVM test on a scratch branch and push | the workflow goes red, and the failing test's name is in the job log |
| `scripts/check-device-gate.sh` | touch `app/src/androidTest/kotlin/.../PanelSmokeTest.kt` with no new ledger row | exit 1, naming the newest row's commit |
| `check-docs.sh` canary (step 4) | remove the planted violation from the canary's fixture | the canary reports the section failed to detect its own case, exit 2 |
| `check-secrets.sh` canary | already exists (`check-secrets.sh:29-34`) — confirm it still fires under the CI runner's `grep` | a green means the scan ran, not that it found nothing |
| `release` | push with a deliberate R8 keep-rule removed | `assembleRelease` fails in CI, not on a headset |

There is no new JVM test in this task. Say that in the commit rather than leaving it to be noticed.

## Blast radius, and what NOT to touch

- **Touches:** `.github/workflows/ci.yml` (new), `scripts/check-all.sh` (new),
  `scripts/check-device-gate.sh` (new), `scripts/check-docs.sh` (canary only),
  `docs/DECISIONS.md` (one new entry + one status line), `docs/DOCMAP.md`, `README.md`.
- **Do not touch:** any `build.gradle.kts`. The toolchain fix (H-37), the convention plugin
  (E-19/H-39), `verification-metadata.xml` (H-13) and the Kotlin/AGP bumps (H-16, H-18) are all
  things that *should be attempted behind CI*, which means after this task, not inside it.
  `keystore.properties` and signing — T-039. `versionCode` stamping from git (H-31) — T-038; this
  task only passes `-PversionCode` through the mechanism that already exists.
  `ModelDownloadReachabilityTest` — do not move it into CI to get "one more test running"; it
  would make this project's build depend on Hugging Face's uptime.
- **Watch for:** `check-docs.sh` section 9 resolves commit SHAs against history, so a shallow
  checkout breaks it — hence `fetch-depth: 0` in the `checks` job. And `check-secrets.sh` relies on
  `git grep`; a detached-HEAD checkout is fine for it, but a checkout with no `.git` would not be.
- **Neighbouring breakage:** turning CI on will surface failures that are real and pre-existing —
  `lintDebug` has never run in this configuration, and `check-docs.sh` is green today only against
  the current tree. If the first run is red for a reason outside this task, **do not weaken the
  gate to make it green**; open a row and say so. That reflex is the whole reason the three
  incidents above lasted as long as they did.
