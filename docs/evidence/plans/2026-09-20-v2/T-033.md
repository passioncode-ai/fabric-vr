## What is wrong, in the person's terms

There is a microphone icon in the Today header. It does not record. It opens a chat screen that
reads the person's notes, sends up to 12 000 characters of them to `openrouter.ai`, answers from
whatever it happened to read, and forgets the whole conversation when Back is pressed. No string in
the app says the notes left the device.

For an operator who dictates in Russian, the retrieval half returns nothing at all (G-04), so the
"most relevant notes" the assistant reads are simply the twenty-two most recent ones — and the
answer reads exactly as confident as one drawn from the right notes would.

## Where it is

**The route and its entry point.** `app/src/main/kotlin/ai/passioncode/fabricvr/ui/FabricApp.kt`:

```kotlin
const val CHAT = "chat"                                        // :20
…
onChat = { nav.navigate(Routes.CHAT) },                        // :47
…
composable(Routes.CHAT) {                                      // :70-75
    ChatScreen(onBack = { nav.popBackStack() }, onSettings = { nav.navigate(Routes.SETTINGS) })
}
```

**The icon.** `TodayScreen.kt:128`:

```kotlin
SmallAction(stringResource(R.string.label_assistant), Icons.Filled.Mic, onChat)
```

A microphone glyph, one slot away from the control whose whole job is the microphone (D-29, G-15).

**The context window.** `feature-assistant/src/main/kotlin/ai/passioncode/fabricvr/assistant/NotesContextBuilder.kt`:

```kotlin
suspend fun build(question: String, budget: Int = 12_000): Context {   // :27
    val terms = TOKEN.findAll(question).map { it.value }.filter(StopWords::isSignal).toList()
    val matching = if (terms.isEmpty()) emptyList() else repository.searchAny(terms, MATCH_LIMIT)
    val recent = repository.recent(RECENT_LIMIT)                        // :29-30
…
private const val MATCH_LIMIT = 20                                      // :64
private const val RECENT_LIMIT = 40                                     // :65
```

At ~540 characters per rendered dictation the budget fits about twenty-two notes, whatever the base
holds. Ordering is `updatedAt DESC` — recency, not relevance. `searchAny` goes through the FTS4
index whose tokenizer case-folds ASCII only (G-04, `core-notes/.../db/NoteEntity.kt:33`,
`core-notes/schemas/…/2.json:136`), so for a Russian question `matching` is empty and the context
**is** `recent(22)`.

**The disclosure.** There is none. `grep -rn "OpenRouter" app/src/main/res core-common/src/main/res`
returns a key field and four error messages. Speech has three explicit disclosure strings
(`provider_local_note` / `provider_cloud_note` / `provider_server_note`,
`app/src/main/res/values/strings.xml:130-132`); the text path has zero. The nearest thing,
`chat_reading` (`strings.xml:96`, "reading: %1$s"), is assigned **after** the request is enqueued —
`ChatViewModel.kt:78`, which runs after `Graph.assistant.ask()` at `:72` has already built the
context and sent it.

**The conversation.** `ChatViewModel.kt:35` is a plain `ViewModel` scoped to the
`NavBackStackEntry`. `onBack = { nav.popBackStack() }` (`FabricApp.kt:72`) destroys it: the
messages, the streamed answer and `usedTitles` are gone, and there is no Copy control on a message.

**The system prompt.** `NotesContextBuilder.kt:70-77`, English, while every note in it and every
question asked of it will be Russian.

## The three answers

### Option A — cut it from v1 *(recommended)*

Delete `Routes.CHAT` and its `composable` block (`FabricApp.kt:20,47,70-75`), the header action
(`TodayScreen.kt:128`), and the OpenRouter block in Settings. Keep `feature-assistant/` in the
repository, compiling, untouched, with its tests — this is a route being closed, not code being
thrown away.

**What it costs:** the feature. The operator loses "ask my notes a question" on the headset.

**What it buys, measured:**

| Finding | Status after the cut |
|---|---|
| G-03 (notes to OpenRouter, undisclosed) | gone — there is no egress |
| G-11 (a 22-note window presented as the base) | gone |
| G-14 (the conversation dies on Back) | gone |
| G-28 (the "reading:" line is post-hoc) | gone |
| G-15 / D-29 (a microphone icon that is not the microphone) | gone |
| B-22 (three chat examples hard-coded in Kotlin) | gone, and T-034's prerequisite 2 with it |
| D-02 (`OPEN_APP_SETTINGS` opens our own screen) | one of its two call sites gone (`ChatScreen.kt:58`); `TodayScreen.kt:287` remains, T-009's ground |
| T-014 (text entry in the Space) | one fewer screen needing a keyboard |
| T-025 (say what leaves the device) | loses its hardest case; the speech disclosures remain |

It also removes the only place in the product where a person's note **text** — the distilled
version, not the audio — leaves the headset.

**Re-entry condition, written now so the cut is not a deletion of the idea:** T-022 has landed,
Russian retrieval is measured working, and the base is large enough that "summarise what I dictated
this week" is a question worth asking a model. Re-enter as that, which is what a 12 000-character
window actually supports, rather than as open chat over an unbounded base.

### Option B — fix it

"Fixed" is not one change. It is all of these, and the feature is dishonest without any one of them:

| What | Why it is not optional | Cost |
|---|---|---|
| **T-022** — Cyrillic FTS tokenizer | without it `searchAny` returns nothing in Russian and "relevant" means "recent" | already in the plan (Blocker, needed for Search regardless) |
| **Rank by relevance, not `updatedAt`** | `bm25`/`matchinfo` over the FTS index; today a term present only in note #400 can never enter the window | ~1 day with tests; new work, in no other task |
| **A permanent, quantitative disclosure** — "read 22 of your 1 340 notes", shown **before** the send | `chat_reading` is assigned after the call is enqueued (`ChatViewModel.kt:78`); a post-hoc line is a report, not a decision | ~half a day; partly T-025's ground, but T-025 does not currently own this screen |
| **A way to keep an answer** — Copy per message at minimum, *Save as note* properly | the one output worth keeping cannot be kept or copied | ~1 day |
| **A non-microphone icon** | `TodayScreen.kt:128` | minutes |
| **"Answer in the language of the question"** in the system prompt | `NotesContextBuilder.kt:70-77` is English over a bilingual base | one line, one test |

**New work beyond what the plan already carries: roughly 2.5 to 3 days**, plus a screen to maintain
in `values-ru` if T-034 answers "translate", plus a second disclosure surface in every future
privacy review.

**What it still does not fix:** the model is two inches away. The operator works beside a streamed
desktop with an AI assistant session on it. The assistant's advantage is that the notes are already there —
and a 22-note window is a worse version of pasting the notes in by hand.

### Option C — leave it as it is, and accept what it does

No code changes. The register records, explicitly, that v1 ships a screen which:

- sends up to 12 000 characters of the person's notes to a third party with **no string anywhere
  saying so** (G-03 — a Blocker in the audit, downgraded by acceptance rather than by fix);
- reads the twenty-two most recent notes and presents the answer as if it had read the base
  (G-11);
- loses every conversation on Back (G-14);
- wears a microphone icon beside the record button (G-15).

**Rejected as a recommendation, for one reason that is not about effort:** G-03 is the product's
only undisclosed data egress, and `docs/ux/foundation.md` JTBD-03 names that exact anxiety — "my
notes leaving the device without me deciding". Accepting C means the register says the product
decided for the person on purpose. That is a defensible thing to write down; it is not a defensible
thing to leave unwritten. **If C is chosen, a DEC row stating it is part of this task, not a
follow-up.**

## Recommendation

**Cut it (Option A).** Every precondition the feature needs is missing at once, the cheapest of
them is a Blocker in another work package, and the feature's own advantage — proximity to the notes
— is undone by a window that holds twenty-two of them. Cutting removes six findings including one
Blocker, removes a screen from the keyboard problem, removes the translation's hardest prerequisite,
and costs nothing that a person is using today.

- **Touches (A):** `FabricApp.kt`, `TodayScreen.kt`, `SettingsScreen.kt`, `strings.xml`,
  `docs/DECISIONS.md`. Deletes `ChatScreen.kt`, `ChatViewModel.kt`.
- **Do not touch:** `feature-assistant/` itself — the module, its tests and its module document
  stay, and the document gains one line saying the route is closed. `SecureSettings` and
  `KEY_ALIAS` — the cloud-STT key uses them and REQ-006's device observation covers them.
  `NetworkPolicy` — C-01 is T-010's, and cutting this route does not make an unfixed URL parser safe.
- **Watch for:** `ChatScreen.kt:58` is one of the two `OPEN_APP_SETTINGS` call sites D-02 names.
  Deleting it does **not** close D-02; T-009 still has `TodayScreen.kt:287`.
- **Do not delete `label_assistant` and its neighbours by eye.** Six strings look dead and one of
  them may be shared; the `grep` in step 5 is the gate, per string.
