## What is wrong, in the person's terms

`docs/evidence/retro.md` is the file that carries the rules an agent must follow which **no check
can decide**. After two full runs, a 58-finding audit, a 291-finding audit and thirty-one commits,
it is empty:

- **Standing instructions:** zero. The table header is at `:27-28` and the next line is the
  retirement note.
- **Recent log:** zero entries.
- **Retirements:** `*None yet.*` (`:48`).
- **Run stamps:** zero (`:56-57`).
- `docs/evidence/retro/` exists and holds nothing.

Stage 10 has never run. The gate reports nothing because section 9 only checks that SHAs *in* the
retro resolve, and there are none — a count of zero against a non-empty `git log` is a measurable
state the gate cannot see.

The cost is concrete: five incidents from 2026-09-19/20 each produced a rule, each rule is written
in exactly one commit message, and **each of the underlying mistakes was made again during this
audit**. The rule against planted defects that pass exists because one did; the rule about
verifying against the installed build exists because a real fix was nearly rejected as ineffective.

## The decision, and what was weighed

**Chosen: six standing instructions, each with its birth commit and its retire-when; two log
entries; two run stamps; carry-over row 10's waiver marked failed. Nothing is pruned, because
nothing is there.**

The file's own rules constrain this and they are not negotiable (`:16-33`):

- **Max ten standing instructions.** Six proposed leaves four of headroom, which is right — a file
  that opens at its cap has no room for what the next run learns.
- **A rule a check *can* decide is not written here; it is written as the check (grade 1).** Two of
  the six are on their way to becoming checks under T-002 and T-003, so they are born with that as
  their retire-when rather than being omitted — an instruction that will be retired by a check that
  does not exist yet is still the only thing standing between now and that check.
- **No row without a retire-when, written at birth.**
- **Two SHA columns, and every SHA must resolve** — `check-docs.sh` runs `git rev-parse --verify`
  over all of them. Each candidate below names the commit that is the incident.

**Alternatives considered:**

- ***Write the incidents as log entries only, and leave the standing list empty.*** Rejected: the
  log is *queried*, the standing list is *read in full at stage 0*. A rule that only exists in the
  log fires only when someone thinks to look for it, which is the same as not existing — and these
  five rules are precisely the ones an agent needs before it starts, not after it suspects.
- ***Write all seven of axis F's candidates as standing instructions.*** Rejected: two of them are
  already checks or already decided, which is the bar at `:18-20`. They go in the log.
- ***Wait until stage 10 of a future run.*** Rejected: stage 10 has never run, twice. Waiting for
  the mechanism that has already not happened is how the file got to thirty-one commits empty.

## Blast radius, and what NOT to touch

- **Touches:** `docs/evidence/retro.md`,
  `docs/evidence/specs/2026-09-19-v1-notes-core-carryover.md` (two rows),
  `scripts/check-docs.sh` (three checks).
- **Do not touch:** `docs/evidence/retro.md`'s doctrine sections (`:1-33`, `:35-54`, `:50-61`).
  They explain why the file is shaped as it is — the cap, the two SHA columns, the read-in-full
  versus queried split — and they are correct. This task fills the file, it does not redesign it.
- **Do not exceed ten standing instructions,** and do not "temporarily" go to eleven. The cap is
  the whole mechanism: at eleven rows the oldest never-fired row goes, and a file that quietly
  holds twelve is a file nobody reads in full at stage 0, which is the volume failure the cap
  exists to prevent.
- **Do not write a rule a check can decide.** Every one of the six above is a judgement about *how
  to work*, not a property of the tree. "Every `Coverage:` path resolves" is a check (T-042);
  "a gate is not a gate until a violation has been planted" is a rule, because no script can
  decide whether you planted one.
- **Do not fill `Last fired` / `Fired at` on birth.** An instruction that claims to have fired
  before it existed makes the cold-retirement trigger unusable, which is the one mechanism keeping
  the list at ten.
- **Watch for:** `8c5ff9e` is the audit commit and it is `HEAD` at the time this spec is written.
  By the time this task runs, instruction 6's incident commit should be whichever commit carries
  the merge's *Method* section — check with `git log --oneline -S 'died on a model spend limit'`
  rather than copying the SHA from here.
