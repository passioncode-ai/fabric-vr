## Correction to the finding

**F-07 is wrong about why `VoiceCaptureSheet.kt` survived**, and the real reason is worse.

F-07 states: *"`python3 docs/ux/lint.py` still exits 0 — it does not check that a `Coverage:` path
resolves."*

It does check. `docs/ux/lint.py:193-215` is `coverage_claim()`, whose entire job is resolving
cited paths, and `:969-970` raises an **error**, not a warning:

```python
                for rel in missing:
                    err(f"[U056] screens.md: {sid} cites '{rel}', which does not exist")
```

Driven directly against the live value, it answers correctly:

```
$ python3 -c "...; print(m.coverage_claim('app/src/main/kotlin/ai/passioncode/fabricvr/ui/VoiceCaptureSheet.kt', Path('.')))"
(False, ['app/src/main/kotlin/ai/passioncode/fabricvr/ui/VoiceCaptureSheet.kt'], [])
```

The check works. **It is never reached**, because the entry parser returns nothing for this file.
`_entry_header_re` (`docs/ux/lint.py:67-69`) requires three hashes:

```python
def _entry_header_re(prefix: str) -> re.Pattern:
    return re.compile(rf"^###[ \t]+({prefix}-\d+)\b[ \t]*(:?)[ \t]*([^\n]*)$",
                      re.MULTILINE)
```

`docs/ux/screens.md` writes its eight entries with **two**: `## SCR-01: Today (home)` at `:39`,
`## SCR-03: Voice capture sheet` at `:64`, and so on. Measured:

```
screens     SCR entry_blocks: 0   index_ids: 8
scenarios   SCN entry_blocks: 15  index_ids: 15
flows       FLW entry_blocks: 6   index_ids: 6
foundation  JTBD entry_blocks: 3  index_ids: 3
```

`screens.md` is the only file in `docs/ux/` that does it, and the consequence is not one missing
check: **the entire screen-level block of the linter (`lint.py:934-980`) never executes.** No
Figma-frame check, no Coverage-exists check, no Coverage-span check, no drift status, no
`built`-without-coverage warning. Eight screens are invisible to their own linter.

Worse, the check that would have caught *that* is defeated by the same emptiness. `lint.py:859-868`
compares the index against the entries and would report eight ghosts —

```python
        entries = set(ids(text, pref))
        if not entries:
            continue
```

— except that `if not entries: continue` is the progressive-arming guard, and zero entries reads
as "this layer does not exist yet" rather than "this layer failed to parse".

**Consequences for this task.** The fix for F-07 is not a new check; it is two characters per
heading in `screens.md`, and it costs nothing. The new backtick-path check in `check-docs.sh` is
still worth building — it covers prose everywhere, not just one field in one file — but it would
**not** have caught this one, because `screens.md`'s Coverage values are not backticked. Two
mechanisms, two fixes, and the spec below does both.

## The decision, and what was weighed

**Chosen: four new sections in `check-docs.sh`, binding on a declared set of *live* documents,
with a tracked allow-list carrying a reason per entry — plus the two-character `screens.md` fix
that re-arms an existing check.**

### Why a *live set* rather than all of `docs/`

Measured over every markdown file in the repository, a naive backtick-path check reports **321
unresolved tokens out of 731**. Almost all of them are correct prose:

- `app/.../Graph.kt`, `feature-vault/.../Vault.kt` — deliberate elisions, ~150 of them, mostly in
  audit reports.
- `ui/TodayScreen.kt`, `theme/Tokens.kt` — suffix references.
- `../research/2026-09-19-scope-pivot.md` — document-relative.
- `ui/HoldToTalkButton.kt`, `ui/VoiceCaptureSheet.kt` in `docs/evidence/audits/2026-09-19-v1-audit.md`
  — a **dated audit** correctly describing a tree that existed then.

A gate that reports 321 findings on its first run is a gate somebody deletes. So the scope is the
documents that describe the tree **now**:

```
README.md  CONTEXT.md
docs/DOCMAP.md  docs/DECISIONS.md  docs/OPEN_QUESTIONS.md
docs/modules/*.md  docs/ux/*.md  docs/product/*.md
docs/evidence/verification.md  docs/evidence/backlog.md  docs/evidence/retro.md
```

Dated artefacts — `docs/evidence/audits/**`, `docs/evidence/plans/**`, `docs/evidence/specs/**`,
`docs/handoff/**`, `docs/research/**` — are out of scope **by kind, not by convenience**: their job
is to record a moment, and a moment legitimately names files that were and files that will be.
Write that reason into the script, or the exclusion reads as laziness.

### The resolution rules, so that a correct reference is not a finding

A backticked token is a path candidate when it matches `^[\w.@+-]+(/[\w.@+-]+)+\.[A-Za-z]\w{0,5}$`
— it must carry a slash **and** an extension. (That narrowness is `docs/ux/lint.py:127-136`'s, and
its comment records that widening it flagged three correct prose entries. Do not widen it.)

It resolves if **any** of these is true:

1. it exists relative to the repository root;
2. it exists relative to the **document's own directory** (`docs/modules/README.md:5` cites
   `../DOCMAP.md` and is right);
3. with `...` or `…` replaced by `*`, it globs onto a tracked file (`app/.../Graph.kt` →
   `app/src/main/kotlin/ai/passioncode/fabricvr/Graph.kt`);
4. it is a **suffix** of a tracked path (`ui/TodayScreen.kt`, `theme/Tokens.kt`).

Rules 3 and 4 are not leniency; they raise coverage. Without rule 3 an elided path would be exempt
and unchecked forever, which is how `app/.../VoiceCaptureSheet.kt` would keep passing.

With those rules, over the live set: **123 candidates, 55 unresolved.** That is a number a person
can read, and it decomposes cleanly:

| Kind | Count | Disposition |
|---|---|---|
| `docs/evidence/plans/2026-09-20-v2/T-0NN.md` rows in `backlog.md` | 37 | **future files** — see below |
| `wireframes/SCR-0N.md` in `screens.md` | 8 | **real** (F-27) |
| `references/documentation.md`, `references/backlog.md`, `references/retrospective.md` | 4 | **external** — task-pipeline's own docs, not in this repo |
| `docs/evidence/retro/YYYY-QN.md` | 2 | **template placeholder** |
| `docs/modules/notes-core.md` in `DOCMAP.md:74` | 1 | **real** (F-25) |
| `scripts/exposure.sh` in `verification.md:55` | 1 | **real** (F-15) |

Ten real findings. Forty-five legitimate. That ratio is what the exemption design has to serve.

### How to avoid a false positive on prose that legitimately names a future file

Three mechanisms were weighed. **Two are adopted, one is rejected.**

**Adopted — a tracked allow-list with a reason per line**, `docs/.docpaths-allow`:

```
# One path per line, then a reason. A line with no reason is a failure of this file,
# not an exemption. Reviewed whenever the gate's unresolved count changes.
references/documentation.md        external — task-pipeline's own reference, not vendored here
references/backlog.md              external — idem
references/retrospective.md        external — idem
docs/evidence/retro/YYYY-QN.md     template placeholder in the retro's own format block
```

Four entries, all genuinely external or literal-placeholder. It is deliberately small and
deliberately annoying to grow: the reason column is what stops it becoming a silencer.

**Adopted — a ratchet, not a pass/fail, for the rest.** `DOCPATH_FLOOR`, set on adoption to what
the repository measurably has (the 37 unwritten spec files plus the 10 real findings, minus
whatever this task fixes), printed beside the verdict, and allowed only to fall. This is the
pattern `check-docs.sh` already uses twice (`PROP_FLOOR`, `RESIDUE_FLOOR`, `:50-63`) and its
rationale is written there: *"the history becomes one printed number instead of a thousand
failures nobody will fix."* The board's 37 forward references are exactly that history — they are
**correct today and will resolve as the specs land**, and every one that lands lowers the floor by
one. A forward reference is not a lie; it is a promise with a due date, and a falling number is
what proves the date is being met.

**Rejected — an inline marker** (`` `path/to/future.kt` <!-- planned --> ``). It puts the
exemption where the claim is, which sounds right, and it is how `check-docs.sh` already handles
one case (`/planted/` at `:88`). Rejected because it is invisible in the rendered document: a
reader sees an ordinary path reference, and the exemption is a fact about the gate that only the
gate can see. The allow-list is worse to write and better to audit, and auditability is the whole
point.

**Also rejected — exempting `backlog.md` wholesale.** It would remove 37 of 55 in one line, and it
would also remove the board's ability to catch a row pointing at a spec that will never be
written. The ratchet gives the same quiet and keeps the signal.

### The other three sections

**Commands (F-15).** Same extractor, different predicate: a backticked token beginning `scripts/`
must exist and be executable; a token beginning `./gradlew ` must name a task Gradle knows. The
second is expensive (`./gradlew tasks --all` is a configuration run) — **do it against a
cached task list, or not at all.** Recommendation: check `scripts/*` now, and record the Gradle
half as deliberately not built, with the reason. A check that adds 40 seconds to every doc gate
will be the first thing switched off.

**Symbols (F-06, F-10, F-13).** In `docs/modules/*.md` only: a backticked token matching
`^[A-Z][A-Za-z0-9]*(\.[a-zA-Z][A-Za-z0-9]*)?$` (a type, or a type plus a member) must appear
somewhere under `app/ core-*/ feature-*/ src/`. `git grep -q` per token. This is the check that
would have caught `onTerminate` (F-13 — it appears nowhere in the tree), `VoiceCaptureSheet`
(F-06) and `HoldToTalkButton`. Restrict it to `docs/modules/` deliberately: those files are
contracts about code. Anywhere else the same regex would match ordinary capitalised prose in
backticks.

**Counts (F-21, F-22, F-23, F-34).** Match `(\d+)\s+JVM tests` and `(\d+)\s+instrumented tests` in
the live set, and compare against a counted value. The count is per-module where the sentence is
in `docs/modules/<m>.md`, and whole-tree in `README.md`:

```bash
count_jvm() { grep -rn '@Test' --include='*.kt' "$1"/src/test 2>/dev/null | wc -l | tr -d ' '; }
```

Measured today: `core-notes 17 · core-common 17 · feature-stt 27 · feature-vault 14 ·
feature-assistant 24 · app 23` = 122, and 15 instrumented across 7 classes.

**Ledger staleness (F-33).** For every `Observed at <sha>` in `docs/evidence/verification.md`:
`git rev-list --count <sha>..HEAD`. Print it. **Do not fail on it** — a row being behind is a
fact to disclose, not a violation; `verification.md:69-73` already defines the four states and
asks for exactly this. Failing would make every commit red. Printing is what the file was written
expecting.

## Decomposition

**Step 1 — write the failing check first, as a canary fixture.** Before touching
`check-docs.sh`, create `scripts/fixtures/docgate/` (or a `mktemp` tree the canary builds) holding
one markdown file per new section with one planted violation each: a backticked path that does not
exist, a `scripts/nope.sh`, a `` `NoSuchSymbol` `` in a module doc, a `999 JVM tests` claim. Run
the script against `DOCS_DIR=<fixture>` and **watch each new section report it**. This is H-12's
requirement and this repository's own standing instruction (`F.md:217`): *a gate is not a gate
until a violation has been planted and watched failing it.*

**Step 2 — section 11: backticked paths resolve.** Extend `scripts/check-docs.sh`. Place it
**before the VERDICT block at `:531`** — the script's header (`:12-14`) records that a section
appended after the verdict printed FAIL and returned 0. Portable bash 3.2: no `grep -P`, no
`mapfile`. Reuse `flat_of()` (`:98`) so fenced blocks are already stripped, and reuse `$TMP`.

The live set is a literal list in the script, with the by-kind reason for the exclusion written
above it.

**Step 3 — `docs/.docpaths-allow`**, four entries, reasons mandatory, plus a self-check: an
allow-list line whose path now *resolves* is itself reported, so the file shrinks as reality
catches up.

**Step 4 — section 12: commands.** `scripts/*` only. State in a comment that the `./gradlew`
half was considered and left out because a task-list resolution costs a configuration run.

**Step 5 — section 13: symbols in `docs/modules/*.md`.**

**Step 6 — section 14: stated counts.** Fail on a mismatch. This one is worth failing rather than
ratcheting: there are seven occurrences, three are wrong, and fixing all seven is ten minutes.

**Step 7 — section 15: ledger staleness, informational.** Prints one line per `Observed at` with
the commit distance. Never fails.

**Step 8 — fix `docs/ux/screens.md`'s eight headings** from `##` to `###` (`:39, 54, 64, 76, 85,
95, 106, 115`). Then re-run `python3 docs/ux/lint.py` and **expect it to go red** with, at
minimum, `[U056]` for the two `VoiceCaptureSheet.kt` citations and `[U020]` for the Figma frames.
That red is the finding, not a regression. Two of those are F-07's and belong to T-042; this task
**re-arms the check and records what it now reports**, it does not fix the screens themselves.
Say so in the commit, and open the rows.

Do **not** edit `docs/ux/lint.py`. It is the super-ux pack's file, vendored; a local edit is drift
that the next `/ux` run will overwrite. Fix the project's own document instead.

**Step 9 — the ten real unresolved paths.** `docs/modules/notes-core.md` → `core-notes.md`
(one word, F-25). `scripts/exposure.sh` in `verification.md:55` → either vendor the script or
replace the section with what this project can run (F-15 — and note it **blocks** the staleness
disclosure in step 7 only if the file keeps claiming a tool that does not exist; step 7 makes the
claim true). The eight `wireframes/SCR-0N.md` → `none — text-only for v1`, which is what carry-over
row 2 actually decided (F-27).

**Step 10 — `DOCMAP.md`**: add `DOCPATH_FLOOR` to the Ratchets table with its adoption date and
value, and add the four new sections to whatever the Gates table becomes after T-002.

## Tests

The gate's tests are its canaries. Each must be watched failing before it is believed.

| Canary | Plants | Asserts | Watch it fail first |
|---|---|---|---|
| `path resolves` | `` `docs/nope/gone.kt` `` in a fixture doc | exit non-zero, naming file and line | remove the planted line → section reports 0 |
| `path resolution is not too strict` | `` `app/.../Graph.kt` ``, `` `ui/TodayScreen.kt` ``, `` `../DOCMAP.md` `` from `docs/modules/` | **exit 0** — these are correct references | break rule 3 or 4 and watch the fixture go red; that is the false-positive guard |
| `allow-list entries must carry a reason` | a bare path line in `docs/.docpaths-allow` | exit non-zero | — |
| `allow-list entries that now resolve are reported` | add `README.md` to the allow-list | reported as stale exemption | — |
| `command exists` | `` `scripts/nope.sh` `` | exit non-zero | — |
| `symbol exists` | `` `NoSuchClass` `` in a fixture `docs/modules/x.md` | exit non-zero | — |
| `stated count matches` | `999 JVM tests` in a fixture module doc | exit non-zero, printing stated vs counted | — |
| `staleness prints and does not fail` | an `Observed at <old sha>` row | a printed distance, exit 0 | — |
| `screens.md entries are parsed` | after step 8 | `python3 docs/ux/lint.py` reports `[U056]` for both `VoiceCaptureSheet.kt` citations | run it *before* step 8: `OK — docs/ux is consistent`, exit 0, over a file naming a deleted class twice |

The last row is the whole task in one line: the check existed, it was green, and it was green
because it never ran.
