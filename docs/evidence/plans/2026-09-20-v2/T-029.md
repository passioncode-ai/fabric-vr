# T-029 — Tags are reachable

- **Severity:** Blocker
- **Work package:** WP-5 (the Today surface)
- **Closes:** D-01, B-02 (the tag-chip element; T-028 owns the rest of B-02 — the split table is in
  that spec)
- **Depends on:** T-028. Also **T-026**, which bounds the queries this screen drives.
- **Needs a headset:** no
- **Estimated blast radius:** `TodayScreen` (one chip row), 2 strings, 1 Compose test. **Zero
  view-model changes** — every method and every state field this needs already exists and is
  already tested.

## What is wrong, in the person's terms

The product's tag feature is complete except that nobody can reach it.

A person writes `#idea` in three notes. `TagParser` parses it (`core-notes/.../TagParser.kt:9-15`),
`RoomNotesRepository.upsert` stores it (`NotesRepository.kt:89-93`), `observeTags()` derives the
list (`:70-78`), `observeNotes(tag)` filters by it (`:64-66`), `NotesViewModel` puts the list and
the selection in state (`NotesUiState.tags`, `.selectedTag`, `NotesViewModel.kt:57-58`, `:112-113`)
and exposes the action:

```kotlin
fun selectTag(tag: String?) { tagFilter.value = tag }      // NotesViewModel.kt:130
```

Then they return to Today and there is **no control**. `TodayScreen.kt:110-219` renders a header, a
banner, the record control, two transient lines and a list. `grep -rn "selectTag\|state.tags\|selectedTag" app/src/main/kotlin`
finds the view model and nothing in any composable.

SCN-003 steps 2-4 cannot be performed at all. The tag is written, stored, indexed, and invisible.

The repository half is not speculative code — it is covered:
`NotesRepositoryTest.kt:100-107` asserts that removing `#plan` from a body removes the tag and that
`observeNotes(tag = "plan")` then returns nothing. The tests pass. The feature does not exist.

## The decision, and what was weighed

**Chosen: a single-select `FilterChip` row between the day card and the record control, with an
"All" chip, hidden entirely when there are no tags.**

**Alternatives considered:**

- *Multi-select (intersection of tags).* Rejected on the API: `observeNotes(tag: String?)` takes one
  tag (`NotesRepository.kt:19`, `NoteDao.observeByTag` at `:16-20`). Multi-select means a new query
  with a dynamic `WHERE`, which means `@RawQuery` or a `LIKE` chain — a data-layer change inside a
  WP-5 screen task, in a module T-022 and T-027 are both migrating. Single-select is what the code
  offers and what one person filtering their own notes needs.
- *A dropdown of tags instead of chips.* Rejected: B-09 is unresolved — a `DropdownMenu` is a
  `Popup`, a second window on the panel's `VirtualDisplay`, and whether it composites into the panel
  texture **and** receives injected input is unverified. Putting the only route to a feature behind
  an unproven widget is how *Transcribe again* became unreachable in the Space.
- *Chips at the top of the list, scrolling with it.* Rejected: they are a filter for the list, so
  they must not scroll away from it. And T-030's whole problem is that the outer `Column` does not
  scroll — putting a row inside the `LazyColumn` would make the filter disappear the moment the
  person scrolls to find what they filtered for.
- *A separate Tags screen.* Rejected: a new route and a new back step for a row of words, in a
  product whose stated shape is one screen (`TodayScreen.kt:63-72`).
- *Show the chips only when there are tags.* **Chosen, and it is the alternative to an empty-state
  message.** See below — it is the one real decision in this task.

## The empty-tag case, which is the only thing here worth arguing about

Three situations, and they must not be conflated:

| Situation | What shows |
|---|---|
| **No tags exist anywhere** (a fresh install; nobody has written a `#`) | **nothing at all.** No row, no "no tags yet", no hint. A person who has never used tags should not be told about a feature by an empty container. The row appears the first time a `#` is parsed, which is its own discovery. |
| **Tags exist, none selected** | the row: `All` (selected) + one chip per tag, sorted — the order `observeTags()` already produces (`NotesRepository.kt:76`). |
| **A tag is selected and its notes are all deleted** | the chip **stays** and the list shows `today_no_tagged_notes` — «Nothing tagged #%1$s.» with the tag name. Then `All` puts them back. Falling back to *All* silently would make a delete look like a filter that broke. |

There is a fourth, and it is the one a naive implementation gets wrong: **a selected tag that stops
existing** — the person edits the last `#idea` out of the last note while the filter is on.
`observeTags()` re-emits without it, `NotesViewModel.observe()` re-emits `selectedTag = tagFilter.value`
(`:113`) which still holds `"idea"`, and the chip row renders a selection for a chip that is no
longer in the list. The list is empty and there is no chip to press to escape.

**Fix it in the composable, not the view model**: render the selected tag as a chip even when it is
absent from `state.tags`, so there is always something to deselect. This keeps the view model —
which is tested and correct — untouched, and it is one line:

```kotlin
val chips = (state.tags + listOfNotNull(state.selectedTag)).distinct()
```

The test below is the one that pins it.

## Decomposition

**Step 1 — write the failing tests first.**
`app/src/androidTest/kotlin/ai/passioncode/fabricvr/TodayScreenTest.kt` (created by T-028):

```kotlin
@Test fun `a tag chip narrows the list and releasing it widens the list`() {
    // seed: two notes, one carrying #idea
    rule.onNodeWithText("#idea").assertIsDisplayed().performClick()
    rule.onAllNodes(hasTestTag("note-row")).assertCountEquals(1)
    rule.onNodeWithText(s(R.string.label_all_tags)).performClick()
    rule.onAllNodes(hasTestTag("note-row")).assertCountEquals(2)
}

@Test fun `no chip row is shown when no tags exist`() {
    rule.onNodeWithText(s(R.string.label_all_tags)).assertDoesNotExist()
}

@Test fun `a filter with no matches says so and can be released`() {
    // seed a tag, select it, delete its note
    rule.onNodeWithText(s(R.string.today_no_tagged_notes, "idea")).assertIsDisplayed()
    rule.onNodeWithText(s(R.string.label_all_tags)).assertIsDisplayed()
}
```

**Watch all three fail.** The second one is the trap: it passes today for the wrong reason — there
is no chip row at all — so it must be re-run **after** step 2 to be worth anything, and the commit
must say so. A test that is green before and after a change has proved nothing about the change.

Add the JVM test that covers the vanishing-tag case, where it is cheap:

```kotlin
// app/src/test/.../NotesViewModelTest.kt
@Test fun `a selected tag survives its last note losing it`() = runTest {
    // upsert a note with #idea, selectTag("idea"), upsert the note without #idea
    assertEquals("idea", viewModel.state.value.selectedTag)   // still selected
    assertTrue(viewModel.state.value.tags.isEmpty())          // no longer in the list
    assertTrue(viewModel.state.value.notes.isEmpty())         // and nothing matches
}
```

**This passes today.** It documents the state the composable has to survive, and it is the reason
the `chips` line above exists.

**Step 2 — the chip row.** In `TodayScreen`, between the day card (T-028) and `RecordControl`:

```kotlin
val chips = (state.tags + listOfNotNull(state.selectedTag)).distinct()
if (chips.isNotEmpty()) {
    FlowRow(horizontalArrangement = Arrangement.spacedBy(Tokens.Space.s)) {
        FilterChip(
            selected = state.selectedTag == null,
            onClick = { notesViewModel.selectTag(null) },
            label = { Text(stringResource(R.string.label_all_tags)) },
            modifier = Modifier.heightIn(min = Tokens.Space.controlHeight),
        )
        chips.forEach { tag ->
            FilterChip(
                selected = state.selectedTag == tag,
                onClick = { notesViewModel.selectTag(if (state.selectedTag == tag) null else tag) },
                label = { Text(stringResource(R.string.tag_hash, tag)) },
                modifier = Modifier.heightIn(min = Tokens.Space.controlHeight),
            )
        }
    }
}
```

Three details, each with a reason:

- **`FlowRow`, not `LazyRow`.** Tags wrap onto a second line rather than scrolling off one. A
  horizontal scroller inside a panel aimed at with a ray is a control that moves while you aim at
  it. The file already uses `FlowRow` (`:405`) and already opts into `ExperimentalLayoutApi` (`:73`).
- **`heightIn(min = Tokens.Space.controlHeight)`.** A bare material `FilterChip` is 32 dp.
  `Tokens.Space` declares 72 dp as the floor for "anything else a person taps" and explains why —
  "a ray pivots at the wrist" (`Tokens.kt:34-44`). B-18 is the finding that most of the product
  ignores its own token. **If T-030 has already introduced a shared chip wrapper, use it** rather
  than adding a fourth place that spells the constraint out by hand.
- **`tag_hash`** (`strings.xml:94`, `#%1$s`) already exists and is currently unused. Use it; do not
  concatenate `"#" + tag` in Kotlin — `strings.xml`'s header says Kotlin holds no words.

**Step 3 — the empty result.** In the `when` at `:197-218`, the `state.notes.isEmpty()` branch
currently always shows `today_empty`. Split it:

```kotlin
state.notes.isEmpty() && state.selectedTag != null ->
    Text(stringResource(R.string.today_no_tagged_notes, state.selectedTag), …)
state.notes.isEmpty() -> Text(stringResource(R.string.today_empty), …)
```

**Do not rewrite `today_empty` itself** — it is stale in two ways (G-17) and **T-032 owns it**. This
task only stops it being shown in a situation where it is additionally wrong.

**Step 4 — the strings.**

```xml
<string name="label_all_tags">All</string>
<string name="today_no_tagged_notes">Nothing tagged #%1$s.</string>
```

EN drafts, like the rest; the copy pass is T-032's and the brand pack's.

**Step 5 — Search.** `screens.md:78` promises tag chips in SCR-04 as well (B-23). **Out of scope
here**, deliberately: Search's chips would filter a query's results, which is a different behaviour
with a different empty case, and `SearchViewModel` has no tag state at all (`SearchViewModel.kt:33-58`).
Say in the commit that SCR-04's chips remain unbuilt so T-042 records it as a doc-versus-build gap
rather than assuming this task covered it.

## Correction to the finding

**G-10's proposed fix says "Delete `observeTagBlobs`/`observeByTag` with the dead tag UI".** It was
written before this task existed and it is now wrong: those two queries are what this task renders.
T-026 carries the same correction on its own page; it is repeated here because a developer reading
only the axis report would delete, in the data layer, the thing this spec asks them to render in
the screen.

**D-01's proposed verification — "a UI test that types `#idea`, returns to Today, taps the chip"** —
is right in intent and expensive as written: it needs the editor, the 600 ms autosave
(`EditorViewModel.kt:113`) and a navigation round trip, which makes a flaky test out of a
deterministic behaviour. Seed the tagged note through the repository instead and test the chip. The
"typing `#idea` creates the tag" half is already covered, on the JVM, at
`NotesRepositoryTest.kt:95-107`.
