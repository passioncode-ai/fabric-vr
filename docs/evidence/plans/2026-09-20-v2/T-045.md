## The overlap with T-003, and which part belongs where

They are one problem split by what a machine can decide, and getting the split wrong means writing
the same check twice or neither.

| | **T-003** | **T-045** (this task) |
|---|---|---|
| **Owns** | the **check** — every path, command and symbol named in prose exists — and its CI wiring | the **content** — making the tree pass it, plus everything the check cannot decide |
| Closes mechanically | F-06 (`VoiceCaptureSheet.kt`), F-13 (`onTerminate`), F-25 (`notes-core.md`), F-15's class, F-27's class | — |
| Closes by judgement | — | F-05 (two opposite decisions in one list), F-11, F-12, F-20 (an inverted rule), F-17, F-18, F-31, F-32 |
| Counts | T-003 adds the **count check** (`@Test` occurrences vs stated totals) | T-045 fixes the numbers: F-21 (17), F-22 (122), F-23 (122 / 15), F-10 (27) |
| Deleted files | T-003 adds the pre-commit check over `git diff --diff-filter=D` against `git grep -l` in `docs/` | T-045 removes the references that exist today |

**Rule for the developer:** if the gate can decide it, T-003 writes the gate and T-045 makes the
tree green against it. If no gate can decide it — a decision stated twice in opposite directions,
a rule that is the inverse of the code — it is T-045's alone, and it will always need a reader.
F-05 and F-09 are review findings and always will be; `check-docs.sh` says so in its own header
at `:8-9`, and that disclaimer should stay.

**The overlap with T-032** is narrower: T-032 makes every *string a person reads* true of the build.
F-38's three dead strings are a subset of its sweep. **T-032 deletes the strings; T-045 does not
touch `strings.xml`** — it only records that the residue is gone. Duplicating it is how two
commits fight over one file.

## The decision, and what was weighed

**Chosen: one sweep, after the code has settled, in one commit per document, with every count
recomputed at the moment of writing and every DECISIONS entry annotated rather than edited.**

**Alternatives considered:**

- ***Sweep now, before WP-5.*** Rejected: five of these documents describe surfaces T-028…T-032 are
  rebuilding. This is exactly how F-05 happened — `732c92b` updated the two references it touched
  and left every other one standing.
- ***One commit for the whole sweep.*** Rejected: a diff across six module documents, the README,
  the doc map, the glossary, the board and the decision register is unreviewable, and this is the
  change where review is the only quality mechanism.
- ***Edit the stale `DEC` entries to match the code.*** Rejected, and the register forbids it. A
  decision is a dated record of what was decided and why; DEC-0003 was true when written. The
  correct form is a `Contradicts:`/`Refined by:` annotation on both ends, which
  `check-docs.sh` section 6 then enforces forever.
- ***Regenerate the module documents from the source.*** Rejected: a module document states
  *intent* — why the STT engine is rebuilt per call, why errors are banners — which no generator
  can read. `DOCMAP.md:70` already grades this row `review` for that reason.

**The one structural change worth making beyond the sweep:** `DOCMAP.md:70`'s module-doc
propagation rule is marked `review` and therefore has **no enforcement at all**. The 2026-09-19
reconciliation found 20 stale claims and this audit found 39 one day later. The lesson is not
"reconcile harder" — it is that a rule graded `review` produces a green gate over a document that
names a file deleted a week ago. T-003 is the answer to the mechanical half; recording that
reasoning is T-046's.
