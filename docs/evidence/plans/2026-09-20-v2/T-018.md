## What is wrong, in the person's terms

They dictate a long thought. While it is transcribing — the module doc measures about 14.5 seconds
for the small model, and a `medium`-model run on a 60-second utterance is longer — they go to
Settings and pick a bigger model, or they press *Transcribe again* on an older note.

The app freezes. Not "gets slow": the whole interface stops, including the recording meter and the
Space's panel, for as long as the transcription that is already running takes to finish. On a
Quest 3 that has been measured at up to about 40 seconds. Android kills an app whose input has
been unresponsive for 5.

Then the app disappears and the dictation is gone with it.

## Where it is

Three lines, in two files, and the order they compose in is the defect.

**1. `feature-stt/.../WhisperEngine.kt:86-97` — `close()` blocks the calling thread:**

```kotlin
override fun close() {
    closed = true
    runCatching {
        runBlocking(dispatcher) {          // <- :89. The CALLER waits here.
            if (ctx != 0L) {
                WhisperNative.freeContext(ctx)
                ctx = 0L
            }
        }
    }
    executor.shutdown()
}
```

`dispatcher` (`:32`) wraps `Executors.newSingleThreadExecutor { Thread(it, "whisper") }` (`:31`).
That single thread is the whole point — `whisper.cpp` forbids concurrent access to one context, and
the doc above the method (`:78-84`) is right that the free must happen there. What it does not say
is that `runBlocking` makes the *caller* wait for the queue to drain, and the queue may contain a
`whisper_full` that is 30 seconds from finishing.

`grep -rn "runBlocking" */src/main` → **one hit, this one.**

**2. `app/.../Graph.kt:71-79` — every caller of `close()` is on Main, holding `Graph`'s monitor:**

```kotlin
@Synchronized
private fun localEngine(): WhisperEngine {
    val wanted = whisperModel()
    loaded?.let { (model, engine) ->
        if (model == wanted) return engine
        engine.close()                                     // <- :76
    }
    return WhisperEngine(modelStore(wanted)).also { loaded = wanted to it }
}
```

`@Synchronized` on a member of `object Graph` locks the `Graph` instance itself, so the block above
also blocks any other coroutine that touches `localEngine()`, `sttEngine()` or `withEngine()`.

**3. The two call paths, both on `Dispatchers.Main.immediate`:**

**4. And there is a second context, which the findings do not connect to this.**
`Graph.withEngine`'s `LOCAL` branch (`:138-148`):

```kotlin

    if (model == whisperModel()) {              // :139 — read OUTSIDE the @Synchronized (I-08)
        block(localEngine())
    } else {
        val throwaway = WhisperEngine(modelStore(model))   // :142 — a SECOND native context
        try { block(throwaway) } finally { throwaway.close() }   // :147 — blocking, on Main

```

So *Transcribe again* with a non-selected model holds two whisper contexts at once. With `loaded`
= `large-turbo` (574 MB) and a throwaway `medium` (539 MB) that is **1.11 GB of native memory** on
a device with no swap, alongside Compose, Room and an OpenXR session. And the `finally`'s
`close()` is a second blocking free, on Main, through `rememberCoroutineScope()`.

**5. Two smaller holes in `close()` itself:**

- `closed = true` runs *before* the free (`:87`), so a transcription already queued on the whisper
  thread wakes, sees `closed`, and returns `SttFailed("engine closed")` — the person is told their
  dictation failed when what happened is that the model was changed under it (I-26).
- Nothing guards a second `close()`. The second call dispatches onto an executor that
  `executor.shutdown()` has already stopped; `ExecutorCoroutineDispatcher` falls back to
  kotlinx's default executor on `RejectedExecutionException`, so `freeContext` would run **off the
  whisper thread** — exactly the use-after-free the method's own doc says it prevents (I-25).

**6. Nothing stops a transcription when the screen or the Space goes away** (C-06).
`owners.onDestroy()` cancels `viewModelScope`, but `whisper_full` is a blocking JNI call that
coroutine cancellation cannot interrupt; the whisper thread finishes the job against a dead
activity, on four cores, and the note is never created. The scratch WAV at `VoiceViewModel.kt:117`
is left in `filesDir/audio/` with no note referencing it and **nothing anywhere sweeps that
directory** (`grep -rn 'audioDir\|filesDir, "audio"' app/src/main` → one writer, one delete-on-
cancel at `:201`, no listing).

## The decision, and what was weighed

**Chosen: one owner, one context, one mutex, and a suspending close.**

### The ownership rule, stated so it can be obeyed

> **`WhisperEngine` is never constructed or closed outside `LocalWhisperOwner`.** At most one
> native context exists in the process at any moment. Every use of it goes through
> `LocalWhisperOwner.use(model) { engine -> … }`, which is `suspend`, takes a `Mutex`, and decides
> *inside* that mutex whether the loaded context matches the model asked for. Closing is
> `suspend`, runs the free on the whisper thread via `withContext`, is idempotent, and is
> `NonCancellable` — a caller who walks away must not leave 574 MB allocated.

```kotlin
/**
 * The single owner of the process's whisper context.
 *
 * whisper.cpp forbids concurrent access to one context, so every call already ran on one thread.
 * What was missing is an owner for the context's LIFETIME: `Graph.localEngine()` closed the old
 * engine from whichever thread asked for a new one, with `runBlocking`, while holding `Graph`'s
 * monitor — and every caller was on Main. Changing the model during a transcription froze the app
 * for the rest of it.
 *
 * One context at a time is a deliberate ceiling, not an accident of caching: `large-turbo` is
 * 574 MB and `medium` is 539 MB, and the old `withEngine` could hold both.
 */
class LocalWhisperOwner(
    private val storeFor: (WhisperModel) -> ModelStore,
    private val newEngine: (ModelStore) -> WhisperEngine = ::WhisperEngine,
) {
    private val lock = Mutex()
    private var loaded: Pair<WhisperModel, WhisperEngine>? = null

    suspend fun <T> use(model: WhisperModel, block: suspend (SttEngine) -> T): T = lock.withLock {
        val current = loaded
        if (current == null || current.first != model) {
            current?.second?.close()                       // suspending; frees on the whisper thread
            loaded = model to newEngine(storeFor(model))
        }
        block(loaded!!.second)
    }

    /** Called when the process is done with speech, and from tests. Idempotent. */
    suspend fun release() = lock.withLock {
        loaded?.second?.close()
        loaded = null
    }
}
```

and `WhisperEngine.close()` becomes:

```kotlin
/**
 * Frees the native context on the engine's own thread, without blocking the caller's.
 *
 * It was `runBlocking(dispatcher)`, which held the CALLER's thread until the whisper thread's
 * queue drained — and every caller was on Main, so changing the model mid-transcription was an
 * ANR. `withContext` suspends instead: the free still happens on the whisper thread, the caller
 * still waits for it, and no OS thread is held.
 *
 * NonCancellable because a cancelled close leaks up to 574 MB of native memory that nothing else
 * will ever free.
 */
suspend fun close() {
    if (!closing.compareAndSet(false, true)) return     // idempotent; the old code had no guard
    runCatching {
        withContext(dispatcher + NonCancellable) {
            if (ctx != 0L) { WhisperNative.freeContext(ctx); ctx = 0L }
            closed = true                                // set HERE, after the queue has drained
        }
    }
    executor.shutdown()
}
```

Note what moved: `closed = true` is now set *on the whisper thread, after* everything queued ahead
of it has run. A transcription already in flight completes and returns its transcript instead of
`SttFailed("engine closed")` — I-26, fixed by an ordering rather than by new code. The
`compareAndSet` guard is I-25.

`WhisperEngine` therefore stops implementing `java.io.Closeable` (a `suspend` member cannot
override `close()`). That is the point at which the compiler finds every caller: `Graph.kt:76`,
`Graph.kt:146`, `WhisperEngineTest.kt:49,68,80,95`, `WhisperBenchmarkTest.kt:60`.

`Graph` keeps a `val localWhisper = LocalWhisperOwner(::modelStore)` and loses `loaded`,
`localEngine()` and the `@Synchronized`. `sttEngine()` and `withEngine()` become `suspend`.

### Alternatives considered

- *Keep `runBlocking` but move every caller off Main.* Rejected. It fixes the ANR and leaves the
  hazard: the next caller added on Main reintroduces it silently, and `runBlocking` inside a
  coroutine on `Dispatchers.IO` still parks a pooled thread for 30 seconds. `grep -rn runBlocking
  */src/main` returning **zero** is a checkable invariant; "every caller is off Main" is not.
- *Post the free and return immediately (`dispatcher.launch { free() }`, "post-and-forget", C-03's
  second suggestion).* Rejected. The next `initContext` would then race the pending free for the
  same address space, and the failure would be a native crash with a whisper.cpp stack — ours,
  looking like theirs. The caller must wait; it must wait *suspending*.
- *Keep the throwaway engine in `withEngine` so a re-run does not evict the cached model.*
  Rejected, and this is the real trade in this task. Keeping it preserves the ~2 s model load for
  the next ordinary dictation after a re-run. It costs: two native contexts at once (up to
  1.11 GB), a second close path, and the model check outside the lock (I-08). **The eviction is
  the honest choice**: one context is a rule that can be stated and tested, "at most two, briefly,
  under these conditions" is not. The person pays about two seconds on the dictation after a
  re-run with a different model, and the app stops being able to allocate a gigabyte of native
  memory in a click handler.
- *Pass an `abort_callback` through JNI so a close can interrupt a running `whisper_full` (C-06's
  proposal).* **Not in this task, and it is the right follow-up.** `whisper_full_params` carries
  `abort_callback` / `abort_callback_user_data`, and `feature-stt/src/main/cpp/fabricvr_whisper.cpp:81-122`
  already builds the params struct, so it is maybe fifteen lines of C++ and one `AtomicBoolean`.
  It is excluded because it changes the native ABI, needs its own instrumented test on a headset,
  and would make this diff two reviews instead of one. **What this task delivers without it:** the
  close no longer blocks Main, so the freeze is gone; the *wait* for the running transcription is
  still up to 30 s, but it is a suspended wait that the UI can describe. Raise the abort callback
  as its own row.
- *Make `Graph.settings` suspend as well (C-03, I-21).* Out of scope here — that is T-019. This
  task makes `sttEngine()` suspend, which is the precondition, and T-019 moves the five Keystore
  decrypts inside it off Main.

### What the person sees while the switch happens

Once the close suspends instead of blocking, the app is responsive during a wait that can still be
half a minute. Silence during that wait is a new defect replacing an old one. Add one state:
`VoiceState.PreparingEngine` (or extend `Transcribing` with a `stage`), rendered as
*"Switching to the medium model…"*. One string, one branch, and it is the difference between a fix
and a relocation.

- (b) `sttEngine()` returns a router whose `local` is a thin adapter that calls

## Correction to the finding

**The plan cites A-12. That row is about the database, not the engine.** A-12 is
`core-notes/.../db/NotesDatabase.kt:20-40`: "`MIGRATION_1_2` deletes every duplicate-`dayKey` row
but the oldest, with its text, and emits no `NoteChange`" — a data-loss-on-upgrade finding that
belongs with **T-027** ("a schema change cannot destroy a database"), which is where it will
otherwise be missed.

The A-axis row that belongs here is **A-17**: "`engine()` is invoked on the main thread … and it
performs up to five Keystore decrypts and may call `localEngine()`, whose `close()` does
`runBlocking(dispatcher)` … blocks the **main thread** until the running decode finishes (up to
~40 s measured on this headset) → ANR." A-17 also carries the only *measured* number in this whole
cluster — "~40 s measured on this headset" — which is worth preserving, because everything else
here is derived from reading.

**Three more rows are closed by this change and are listed nowhere:**

- **I-08** — `withEngine` reads `whisperModel()` outside the `@Synchronized`, so a model change
  between the check and `localEngine()` runs the re-run on the other model. The `LocalWhisperOwner`
  mutex makes the check-and-load one critical section, so it goes away rather than being fixed.
- **I-25** — a second `close()` dispatching onto a shut-down executor, which falls back to the
  default executor and frees off the whisper thread.
- **I-26** — `closed` set before the free, so a queued transcription reports `engine closed`.
